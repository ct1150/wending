# 百世问鼎：开始画面与多旅程续玩

日期：2026-10-29（上海）。用户已在 grill-me 中确认全部推荐，包括主入口命名和保留旧旅程的新开行为；本文件记录已确认设计，不再重复索取批准。

## 目标

以独立的极简水墨标题页作为游戏入口。三个固定位置、清楚可见的主入口为「踏入仙途」「续写此生」「游戏设置」。纸色底、淡墨远山、居中游戏名与纵向菜单；手机首屏完整呈现主入口。继续维持剧情与选项为中心的修仙文字肉鸽。

## 已确认的体验

- 踏入仙途：辅助文字「开启一段新的修仙人生」，进入角色创建。用户确认允许人物仍活着时另开独立旅程，原旅程保留且能切回；主动新开不授予死亡结算或轮回奖励。
- 续写此生：辅助文字「从上次停下的地方继续」，恢复上次选择的旅程，展示姓名、境界与进度摘要。无档时禁用并说明原因。菜单位置稳定，只调整主次强调。
- 游戏设置：阅读偏好与存档管理。设置与返回入口不能藏在右上角「更多」。
- 新玩家默认实时剧情；旧离线人生依原规则恢复。两类档案都可经「切换存档」访问，实时旧 run 也须可访问，不能仅声称底层保留。
- 重新打开页面先显示首页；同一标签内刷新恢复所在页面、角色创建草稿或剧情。首页只是读取，不创建人物、掷骰或调用生成。创建草稿在确认入世前不替换活动人物。
- 剧情下方显示「历史对话 · 游戏设置 · 返回首页」。姓名、境界、年龄、余寿仍在顶部，人物详情与历史抽屉保留。
- 自然死亡后的新开入口使用「再入轮回」，先返回姓名/出身创建步骤。保持现有引擎结算，不为首页新开伪造死亡或奖励。

## 实现决定

使用现有原生 JavaScript、CSS 和本地存档，不引入运行时依赖。已有纸页排版与轻量 SVG 远山可复用。保持离线单文件构建、旧存档读取、实时协议和服务端不变。

首页控制与阅读偏好拆至小模块，app.js 负责路由与接线。主题提供跟随系统/浅色/深色，正文大小提供标准/较大；设置立即生效并本地保存。没有现存音频系统，不添加无效音量选项。

实时 IndexedDB 增加只读分页旅程目录和显式活动档切换；保留 pending、attempt 和完整历史。新开使用明确的 expectedArchiveId 检查，多标签旧页面不得覆盖新选择；在途生成不允许本标签切档，新开和切换不自动重试。列表分页只是显示窗口，不限制旅程或回合总量。

离线存档继续使用原活动键。需要替换或切换之前，先持久保存完整原档及旧版交接备份；备份或写入失败不得丢失原档。现有坏档必须保留并提供导出恢复。实时导入与离线导入均需明确用户确认后再切换，原旅程仍可找回。

创建页面的草稿、首页/设置/剧情位置通过当前标签 sessionStorage 保存，只有 reload 恢复路由；普通新访问总从首页开始。存储受限时显示可操作错误，不静默重置存档。

## 方案选择

用户选择极简水墨标题页，放弃视觉更重的山门背景和古籍翻页。选择实时剧情为新玩家默认入口，续写按最后使用的模式恢复。用户确认主菜单使用「踏入仙途 / 续写此生 / 游戏设置」，自然死亡新生另用「再入轮回」。

## 验收

1. 无档首页三入口可见，未创建任何人生或发起生成；新玩家可明确进入实时创建。
2. A 人物仍活着时创建 B；切回 A 后随机状态、待续请求、正文与完整历史一致；刷新和再次打开都可继续。
3. 已有离线档可从首页恢复；新建实时旅程不写坏旧离线进度；坏档与写入失败不触发覆盖。
4. 主页、设置与切档不推进时间、不再次掷骰、不隐式生成；自然死亡走既有结算。
5. 320/390/1280 像素宽度无横向溢出，三个主入口首屏可见，键盘焦点可辨；暗色和大字仍可用。
6. 全仓回归、语法检查、在线/单文件构建通过；提交精确 SHA 的 GitHub CI 通过后合并，核对自动静态频道与生产 health，再实际浏览器验收。
