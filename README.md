## 开始游玩

- **踏入仙途**：第一次为人物取名、选择来处。已有当前人生时直接继续；若人物已死亡，则回到该人生的结算页。
- **续写此生**：恢复唯一的当前存档，包括尚待续写的回合。仅访问首页不会创建人物、掷骰或请求剧情。
- **游戏设置**：调整画面主题和正文字号，可明确确认「重新开始」。新人物成功存入前保留原进度；重开不发轮回奖励。上次确认后若别的标签已换档，本页须重新确认。
- **备份与恢复**：导出当前 `.wending.jsonl`，或只读查看、单独导出先前人生。恢复备份须经校验和确认；在这里查看过去不会切换游玩人物。

剧情上方显示人物状态，正文旁显示当前目标。选项按规则列出时间、灵力和物资成本；知道对手境界时可见胜算概况和缘由。自定义示例只填入文本，提交才行动。游戏需要联网续写；进度保存在当前浏览器，不同设备和域名之间不会自动同步。

## 剧情与玩法

凡人流修仙推演引擎 v7 使用九境修行、独立寿元结算、长期因果导演、自定义行动和真实死亡后的轮回传承。AI 逐段写出原创正文与对白。回合保存后，引擎展示两到三个能执行的行动，还可以输入自定义行动。

v7 在写作前用当前资源、境界、人物和上次行动规划下一步；游戏只会把能按规则结算的行动交给玩家。正文长短由事件需要决定，人物可自然使用别称，观察人手中的物件不必重复人物全名；正常内容直接保存，不额外自动重试。角色数值、身份、生死、收据和存档提交仍由规则保护。模型写的附注是待核实的建议：成立的事实可以留下，不成立的建议不能修改人物或库存，也不必让玩家重走一次已经写完的剧情。

| 系统 | 行为 |
| --- | --- |
| 时间与寿元 | 闭关和赶路增加年龄；血遁、禁术反噬折损寿元上限，延寿灵药提高上限。 |
| 九境修行 | 炼气、筑基、结丹、元婴、化神、炼虚、合体、大乘、渡劫；突破检查修为和材料，并结算风险。 |
| 出生与资源 | 灵根、体质、伴生遗物与初始功法各有特点；炼丹、炼器、制符、布阵消耗实际资源。 |
| 长期因果 | 人物、承诺、线索和既有决定参与后续剧情；窗口外内容可背景化，完整历史仍保留。 |
| 玩家行动 | 数字 1—3 执行当前选项；第四项支持可映射的自然语言行动，拒绝无效行动时不消耗回合。 |
| 轮回 | 仅真实死亡后结算因果点并兑换传承，领取记录随完整备份保存，不能通过恢复旧备份重复领取。 |

登仙和问鼎是人生阶段，不是固定终点；人物存活时可继续选择，游戏不另设回合数或游玩时长上限。引擎提供可执行的选择并结算时间、资源、风险和死亡；模型负责承接刚才的决定，创作剧情与人物对白。真实生成仍受模型质量与网络服务影响。

本次不改变生产模型、免费方案或存档格式：继续使用原 Cloudflare AI binding 和 `@cf/zai-org/glm-4.7-flash`，不接入付费后备。平台额度、网络或服务异常时保留已保存进度与待续回合，可明确重试或检查已有回应，不重复结算同一个选择。

## 新人生的成长与轮回

服务宣告支持新规则后创建的人物才使用本节玩法。原有无标记人生继续按出生时的合同重放；不能因为更换网页而重算过去。服务器暂不支持已标记的人物时，保留其存档和在途请求，等待兼容服务恢复。

| 你做的决定 | 游戏里留下的结果 |
| --- | --- |
| 面对开局 | 出身和已保存的种子决定眼前困境，可能是入门机会、资源紧张、秘密暴露或人际取舍。询问、观察或暂缓不自动接下委托。 |
| 修补残法 | 验法用 1 日、2 灵力；自行推演用 90 日、8 灵力。也可明确接受在场人物的指点，用 3 日、4 灵力完成校法，再遇原人时用 1 日归还一份行粮。完整功法不走这条路线。 |
| 与强敌交手 | 对手的境界首次得到确定依据后按人物身份保留；不明则显示未知。对同一对手，自身晋阶能改变真实判定和伤势。修法保留功法长处，减少对应的灵力、时间、暴露或判定代价。 |
| 决定是否还约 | 泛泛帮忙、拒绝、同名的另一人都不能清偿债务。读档后仍是原来的那一份行粮，交过就不会再扣。 |
| 身故后进入下一世 | 死因、最后行动和未清事项来自已发生的记录。新人生至多选择两项传承，按实际点数付款，余点留存。至多三条可追溯的前世回响会随完整备份保存；回响不自动发放物品或把旧债转给新人物。 |

## 全本参考如何参与剧情

保留 5.3.0 合入的全本 RAG 代码。私有语料导入及实际启用仍属独立发布步骤，本次可玩性修复不改变线上知识库启用状态。

全本证据覆盖 137,443 个符合条件的叙事段落；广告、标题、空白和作者感言的排除范围有逐项核算。7,936 个窗口是可追溯的自动切片，120 张精选卡是独立的抽象改编层；不将窗口数量当作精编卡数量或逐条语义审校结果。[覆盖与重建说明](docs/knowledge/README.md)给出数量、来源校验值和准确边界。

检索优先匹配本次行动，避开近期已用片段，并保留明确拒绝、告辞和失败跨界的结果。每次最多加入一张精选卡和两个证据窗口，总模型输入仍不超过 24 KiB。资料仅提供冲突与动机的参考，不能替玩家接受任务、发放资源、移动位置或改变规则判定。只有成功提交的剧情才更新本局引用历史，重试继续使用原冻结上下文；旧存档的有效内容优先于可选检索字段。

在生产策略有效时，参考资料缺失、损坏或读取超时，仍用原本的游戏上下文生成一次，不伪造引用。无效配置、请求取消和平台免费额度边界继续生效；GitHub 发布 HTML 不会开启生产知识库。


## 单存档与兼容

沿用 `wending-live-v1` IndexedDB 数据库、结构版本 3 和既有当前存档指针。升级直接读取此前实际选中的在线进度，不按时间重新挑选人物、不清空数据库、不改写历史或随机状态。旧导航中的存档列表和离线页面回到首页。

出生与开局待续事务在请求剧情前一起保存，刷新不会重掷。成功保存新人物后，原人物不再作为可切换存档提供；生成暂时失败时，新人物的待续回合可恢复。普通继续不会替换已死亡人物的结算，只有显式重新开始或轮回才创建下一人生。

完整备份保留 V5/CV4、v7 规则标记、格式 1/2/3 和关系记录兼容。导入在完整校验后才激活，跨标签页使用事务与预期身份检查，旧页面和迟到回应不能覆盖已经替换的当前存档。

旧版 localStorage 原始数据和底层历史记录保留供兼容与恢复使用，不作为额外存档槽提供。检测到旧版原始数据时，设置中的「备份与恢复」提供原样下载；旧固定剧情不再接入游戏控制器。

## 开发与构建

Node.js >=22，项目使用 Node 24。Playwright、Miniflare 与 Acorn 仅为开发依赖。

```bash
npm ci --ignore-scripts
npx playwright install chromium
npm run dev
npm run release
```

`npm run release` 执行完整测试、语法检查和网页构建，并重建 `release/`。后端打包须在网页构建之后执行：

```bash
SOURCE_COMMIT=完整40位源码提交 npm run build:gateway
```

| 产物 | 用途 |
| --- | --- |
| `dist/` | 静态网页目录 |
| `release/baishi-wending-web.html` | Worker 内嵌网页发行包，需要在线服务续写剧情 |
| `release/release.json` | `frontend` 字段记录版本、文件、字节数与摘要 |
| `release/gateway.mjs` | 静态发行网关 |
| `release/backend/` | 后端与模块清单；默认构建关闭推理，不可直接替换正式生产包 |

GitHub main 自动发布 HTML，保留既有 schemaVersion 1 的频道清单与不可变摘要路径。正式 Worker 使用内嵌页面，仍需单独更新实际部署并核对版本；离线下载旧地址 `/baishi-wending-offline.html` 返回 `410 Gone`。实际页面身份以 [`/healthz`](https://wending.868656.xyz/healthz) 为准。

## 代码入口

- `src/app.js`、`src/ui/navigation.js`、`src/ui/title-screen.js`：单存档在线流程、首页和设置。
- `src/ui/live-session.js`、`src/game/live-archive.js`、`src/game/live-save-format.js`：当前存档、事务恢复与完整备份。
- `src/game/cultivation/live/`：规则、记忆与轮回。
- `src/ui/journey.js`、`src/ui/character.js`：剧情、历史与人物展示。

旧引擎、旧存档校验器和历史验收保留在仓库中；它们不再由游戏入口启用。此前界面和引擎设计见 [山海墨金界面](docs/superpowers/specs/2026-10-31-cinematic-game-design.md)与[凡人流 v7](docs/superpowers/specs/2026-10-31-cultivation-v7-design.md)。
