## 下一阶段的实质缺口

1. **后段需要持续的主动修行冒险。** 现有云渡、走山驿已经有可用因果，但主路线后段仍频繁回到修炼、寻材和交割。优先在现有地点与人物之间形成一段调查—施术—受阻—改变办法—完成后回访的连续经历；不要靠增加读页或重复闭关填充目标时长。
2. **早期决定需要更多实际后果。** 优先让旧设施、术式与已知线索改变可用路径、付出的真实资源或后续难题。守关不少后果目前落在回执与铭文；不需要把每次离开变成惩罚，也不能反向改写早年的成果。
3. **可错过内容的提示需要更完整。** 行记已经给出日期与跨时限提示，不能笼统称“没有提醒”。但抽查界渡台 `sea-convoy.js:108–112` 只介绍跨界条件，未列离界后不能亲自续办的旧事；`journey-notes.js:113` 的期限筛选针对时日，不等于完整的离界影响说明。新增提示应只展示当前存档实际相关的事，不阻止玩家离开；是否覆盖每条进阶入口仍待定点核验。

## 后续开发与验收方向

下一块内容优先依附上界现有白脊云渡／走山驿，形成由玩家亲自调查与施术的连续险境。先完成一段从入口到结果的可玩闭环，再扩展到后续境界；避免一次性铺设更多不相连的簿册。

- 已练术式应改变解法，不只增加一句描述；无术式人物保留可行且代价明确的路。
- 至少一项既有决定改变现场可观察证据或通路，不预设玩家一定走过某条支线。
- 承担风险前显示真实代价，失败后有继续、补救或退出的路，后果由现有规则结算。
- 同一连续人生验证前因、选择、即时后果、后续回访；未完成时离开、保存、刷新、旧存档恢复均能续接。
- AI 保持非必要，不增加实时生成等待；核心剧情、选项与结算保持确定性。
- 真人试玩手记负责记录有效时间与主观反馈；后台计时、脚本速度和故事文字总量不能取代它。当前二十小时目标仍未验收。
