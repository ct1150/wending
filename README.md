## 2.0.0 怎么玩

确认没有存档时，云归十六岁直接进入谷口情境，不先填角色表。读当前情境，选择接下来要做的事：通常两到三个行动，明确交接与结算边界可只有一个。对白、选择和实际回应保留在同一阅读流中；历世生平、前世行文与已得传承历史可按需展开。身体处境由正文说明，当前物品数量与余寿在相关行动的成本说明旁显示。帮助和“更多”提供说明、导入导出、下载与明确确认的重新开始。

- **调查与救援**：证人、账册、地脉最多深入两条。调查次数是唯一封谷窗口；普通阅读、学习与明示耗年不另扣隐藏八年倒计时。治疗、同意、证物与救援分别记录，关系或能力不会补造证据。
- **经历带来成长**：关键承担开放下一章的通行能力；从凡人走到筑基、结丹、元婴，不需反复刷修为。普通冲突一次选择收束，重要冲突至多三次，不磨血。
- **有限机会与真实代价**：每个大章抽定一次机会且最多学习一项，一世最多三项新能力。可拒学，第一世无可选能力也能通关。需要药包、证物、时间或寿元时，代价与禁用原因写在选项旁。药理学习用一年；连同服务换药共两年。耗年推进年龄和世界，燃命只损个人余寿。
- **同世三界**：药谷交接后活着赴幽冥，再赴天界与问鼎。缺证可以有限补交；让步与责任保留损失，不让死者复生、不令毁种复原。通关不等于所有人都被救下或地方已获足量供药。
- **同一世界的下一世**：真正结束人生后，至多三个选择直接新生，每次仅一项传承方法生效。已得传承历史、道证、世界事实与生平保留，死亡次数不发奖。已完成后世任务只留后果回声，不重复刷取；人随世界年老去，接任者不继承死者的私人关系。

问鼎胜利本身仍是活着的结果；选择再入世时明确走完余寿、写一次生平，再经过十六年新生。医馆、庄园、迁民是三类有限替代后世任务，本版不承诺无限新篇或完整家谱模拟。**20–30 分钟一世与寿元压力仍待真人试玩验证**；动作数和自动测试不能证明阅读时长。

## 存档与旧版继续

产品版本 **2.0.0** 与 JSON 存档版本不同。新旅程使用 **version 3 / dialogue**，仍保存在浏览器键 `baishi-wending-save-v1`。合法 v1/v2 先严格验证，当前人生继续旧规则，包括未完战斗、际遇与明确奖励选择；到结算后才按提示交接进入 v3。旧规则的修行、装备、流派和最多两项携带只服务旧当世，详见 [兼容契约](docs/ENGINE_CONTRACT_V2.md)。

转换前保留可恢复的原始字节备份、当前结算进度与唯一准备的新人生；新档校验、必要备份写入并验证成功后才替换当前档。失败时可导出原档、较新旧进度或准备的新档，重试沿用同一目标，不重复出生或耗年。若备份比当前档更新，须明确恢复后再继续落子。原档与新进度是不同备份，请按实际提示保存。

无效 JSON、空字符串、损坏或读取失败均不会自动被新人生覆盖。一般保存失败仍可导出内存进度；旧档交接或待恢复进度须先解决提示。存档不上传。换浏览器、域名或线上／离线版本请使用导出／导入；`file:` 存储政策可能不同。v3 无法交给旧程序读取，切换前请先导出备份。

## 检查、构建与离线版

```sh
npm test
npm run check
npm run build
```

`npm run release` 顺序执行上述三步。默认 Node 隔离 runner 的数量是**测试文件数**；行为用例数须另行读取独立执行结果。

| 输出 | 用途 |
| --- | --- |
| `dist/` | 静态站点，原生 ES 模块与相对资源路径 |
| `release/baishi-wending-offline.html` | 内嵌脚本、样式、本地 SVG 的单文件版 |
| `release/release.json` | 版本、UTC 构建时间、离线字节与 SHA-256 |
| `release/worker.mjs` | 常规构建后运行 `build:worker` 另行生成的普通 Worker |

离线 HTML 同时复制到 `dist/baishi-wending-offline.html`。构建不改源码，单文件无需外部运行资源。Worker 打包须提供实际源码的完整 40 位 SHA：

```sh
npm run build:worker -- --source-commit ACTUAL_MERGED_40_CHARACTER_SHA
```

以上占位值须替换为真实合并提交；只打包、不发布。正式发行按 [部署流程](docs/DEPLOYMENT.md) 核对精确树、CI、运行时 SHA、health 与下载，不能将合成本地历史当远端发布历史。
