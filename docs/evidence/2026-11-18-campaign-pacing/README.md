基线：`edf6a40b8f5a66252d10ded5f58cb86ed88e4294`。本次只产出调查证据，不修改玩法、不发布生产，也不宣称已经具备20小时真人体验。

## 怎样重现

在仓库根目录运行：

```powershell
node docs/evidence/2026-11-18-campaign-pacing/reproduce.mjs
```

脚本将固定提交解包到新的`.scratch/campaign-pacing-*`，不改工作区源码。它给原有`one continuous birth`测试的动作观察器增加记录，保留到三界终局的原生选择、结算和断言，在浏览器存档重放之前停止。它不运行浏览器、不增加新存档验收、不模拟人类阅读时间。复制的测试中其他测试不执行。

摘要与本目录`summary.json`深比较，失败则退出。原始逐动作记录和完整测试输出留在该次新目录。`sourceHash`对输入测试源码统一LF后计算SHA256，以免Windows检出换行造成伪差异。初次复现确实发现了换行哈希差异；统一口径后重新执行生成和隔离复现，均1/1通过，摘要完全一致。

普通修炼限定动作键`practice/practice-again/practice-intensive`，不包含云渡、守关、种苗等带剧情的闭关。最长连续段为合体706–720回合的15次普通修炼；大乘780–793另有14次。界面已有连续稳修，因此这些数值不能当作必须手动点击的次数。

“事件字段变化”只比较`events`中除`node/page`外的字段；包含选择草案等操作，不能等同有意义的决定。没有字段变化的查阅、对话、辨线索，也不能据此视为无用菜单。分境界字数包含菜单、状态和重复数字变体，各境界集合有重叠，不可相加为独立剧情。全路线记录888种文本块、35224个Unicode码点，也不能换算游玩时长。观察的是入选动作之前的场景，与此前统计动作之后场景的35122字符口径不同。

这条路线没有进入`post/mountain/ferry/forms/cloudRift`。它覆盖主线通关，不覆盖全部现有内容，也不是每位玩家的必经路线。因此本记录只能支持“这条路线后期依赖更多普通修炼”，不能证明“整个游戏后期没有冒险”。

## 对源码的定点核验

- `src/game/cultivation/live/cloud-passage.js`：三班均是选择守候位置、按原功法闭关，再选择一种交班方式。`fits()`主要把工期从九日降为三日；末班分支发雷印或延寿丹，随后进入三次交班总结。
- `src/game/cultivation/live/cloud-rift.js`：首班渡法及听泉/护身术式确实改变可靠通路；不稳试踏会增加一层伤势。再访可以保留或改变此前定脉，有实际成本。原文明确旧渡船仍走旧航道，不能因风隙完成就自动宣称渡船改道。
- `src/game/cultivation/live/mountain-ding.js`：终局选取九关中三足并决定合器/分授，依实际守关记录保留公开或封还。这是可用的收束，不应仅为延长时长再加重复领取。
- `tests/river-chronicle.test.js`：三班云渡的当前长线断言覆盖观察文本、实际工期、两种路线和末班物品；它们不能证明首航的分配、接班冲突或更长期的营运抉择已存在。

一名只读子代理独立检查相关云渡、风隙、折山及长线测试。主代理复核了云渡完整模块、风隙通路与定脉段和测试云渡段。没有将其他未检查模块里是否使用这些结果说成全仓库结论。

## 下一步的具体方向

优先扩展现有云渡的连续试航与交班，而不是继续增加返回按钮或新建彼此无关的小委托。三班应逐步累积可用的交接手段：第一班亲自辨认航路限制，第二班在灯坊轮值与船上报声之间安排交接，第三班处理同一条样船先接候渡者还是先带学徒的问题。后续可执行行动必须由实际记录改变，不能只换描述、三日/九日工期或奖励。

实施前把运输容量、未先服务一方的去处和完成条件写成可检验规则。允许回山和放弃，不让任何选择凭空解决所有人的需求，也不新增强制等待来凑时长。没有风隙经历的人也必须能完整走完；已有风隙经历只能在明确选择借用之后产生新后果，不能倒改已经交班的航次。

保留现有云渡`seat/route`和已经结算的物品、修为与年月。老存档的未完选择先按旧合同恢复；新内容只记新发生的试航或补验，不把完成三班的旧玩家伪装成再次首航。接入位置和新记录结构仍需在实施时结合场景重放精确设计，本文没有把尚未实现的机制写成现有能力。

下一次验收须含无风隙的原生连续路线、两种首航优先次序、前序交班改变实际可用行动、旧档与中断后只结算一次、移动端保存刷新。所有程序验证仍只证明机制；20小时目标继续依赖实际有效游玩和重复感反馈，当前未完成。
