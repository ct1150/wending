## 对下一步的约束

完整性已得到较强的自动证据，但没有20小时真人体验的证据。增加几十个回合、更多修炼按钮或另一份交接清单，不足以关闭这个缺口。

`ridge-road.js` 的验路段在同页直接给出征象与判断规则，错误一次后移除错误选项；旧工程会改变下一段提示及工期。它是有限的线索题和路径后果，不应宣传为复杂多阶段探索。

`expedition.js` 已有明确的地图、不同边长、奇偶潮刻、收集目标和可选绕路；第一程还能使用早先苗契留下的纤道。`cloud-trial.js` 的容量、先后与接班资质则提供资源和人事取舍。这些机制各有用途，但不能反复换名复制同一种“两组人选一组”来填时长。

下一段开发应以一个可连续探索、存在竞争假设、允许不同完成方式的长篇为单位；玩家需要通过行动检验判断，结果改变后续可行路线。旧记录应成为真实工具、证据或约束。可选AI仍只润色已经确定的事实；不会为每个新节点增加运行时生成请求。

应同时保留：不用AI能完整走完、可明确离开、实际资源和修炼成本、旧存档与待续回合、死亡后历史及轮回边界。内容扩展完成后仍须真人实际玩过，按试玩手记扣除休息，并核对中后段体验，才可能证明20小时目标。

## 复核与确定的后续

一名只读代理核查了上述统计口径和三个玩法模块，主代理另核对了实际 `noteRoutes`：自动翻页只遍历允许的菜单步骤，不能把该固定测试路线的导航数当作真人负担。代理提出旧航标探索方向后，主代理完整读取 `cloud-rift.js`，确认合体再访结束页目前有两个选项，旧有效形态必须组合初次定脉与再次改变，而不是只读 anchor。

调查过程中的 `.scratch/combined-pacing.mjs` 是早期脚本，字段名与正式版不同；本目录 `run.mjs` 才是最终生成器，`reproduce.mjs` 已将它复制到固定源码副本执行，并深比较最终摘要。没有用早期脚本的字段名解释正式摘要。
