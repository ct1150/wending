# 百世问鼎

**1.2.0 候选 · 纸页界面**：一款剧情与探索主导的单机文字修仙游戏。你从十六岁入道，走入即将封闭的药谷，结识医者沈芷、封谷执事陆槐与旧掌闸人温渡。在证词、账册和地脉之间选择调查路线，付出药材、灵石、气血或寿元，决定最后一枚灵种和谷民的去向。下一世仍是同一个向前走的世界：医谷的规矩、宗门的药庄，或迁民的新药园，会成为后来人真正可玩的任务。

## 开始游玩

- [线上游戏](https://baishi-wending.ct1150.workers.dev/)：**1.1.0 药谷旧火已上线**，已核实剧情开局、选择与刷新恢复。实际发行源码与上线证据见 [部署记录](docs/DEPLOYMENT.md)。
- 体验本分支 **1.2.0 候选**（尚未发布，浏览器视觉与交互验收待完成）：下载源码后运行 `npm run dev`，或完成构建后打开 `release/baishi-wending-offline.html`。
- [源码仓库](https://github.com/ct1150/wending) · [玩法说明](docs/PRODUCT_SPEC.md) · [验收与限制](docs/QA_REPORT.md)。

游戏在浏览器本地运行，无运行时依赖、玩家账号或游戏后端，不上传存档。使用 Node.js 24 开发，最低 Node.js 22；不需要执行 `npm install`。

```sh
npm run dev
```

打开终端显示的地址，默认端口 `5173`。开发服务器绑定 `0.0.0.0`，支持 `PORT=8080 npm run dev` 和 `npm run dev -- --port 8080`。

## 这一版怎么玩

首次打开且确认没有存档时，直接进入药谷谷口“灰里还有人”，无需先填写角色表。首世使用推荐角色：**云归、山村出身（`village`）、剑修（`sword`）、不带传承**；16岁、120气血、24灵石、3药材、84年自身余寿，距封谷8年。此时还没有替你选择、推进年份或支付费用。已有合法存档时优先恢复原人生，包括尚未完成的际遇、战斗或结算。

纸页主区围绕当前场景、眼前目标、剧情和选择展开。选项展示真实成本、相关资源现有量及禁用原因；选择后的实际后果留在正文中。修炼、休息、炼丹等行动会显示自己的最新结果。调查方向真正出现时，再说明三条路线最多深入两条；距封谷年数与角色自身余寿分别显示。

页面下方按需展开三个入口，阅读记录和换装不花游戏时间：

- **状态**：身体、资源、修为、自身余寿与世界概况。
- **回看**：剧情手记、药谷人物、已知线索、当世记录与历世生平。
- **修行**：修炼、休息、炼丹、自由历练与归隐，并可进入功法与法器、三界山河、轮回传承；独立功能页有返回当前剧情／未完成战斗或际遇的入口。

页首 **帮助** 和 **存档与设置** 提供规则说明、导入导出、离线下载与明确确认的重新开始。结束此生后仍可选择真实经历产生的奖励；开启下一世时，可以完整自定**道号、出身、修行之路与最多两项已有传承**。首世的推荐预设不会取消下一世的角色选择。

- **连续主线与有限支线**：首篇分三章，内容表有 YG01–YG16 十六个核心节点，单次游玩因分支看到不同子集。证人、账册、地脉三线最多追查两条；三种旁支中由种子确定两次机会，不靠重复抽取才能继续主线。
- **三种主要收束**：医谷共守、宗门接管、焚种迁民。轮回后分别进入医馆分诊、药庄契约、迁民药园的五场景后续任务，各有真实选择和结果。提前寿尽、战败或归隐也留下未竟记录。
- **可解释的取舍**：剑修、体修、丹修有不同调查和过门方法，存在不战斗完成主线的路线。可选剧情短战最多三回合，胜利、撤退和死亡均有后续。
- **共享时间与世界**：调查有八年封谷期限。普通修炼、休养和旅行也推进世界年份，可能错过调查；到期仍有应急退路。燃寿损耗个人余寿，普通战斗回合不让世界逐年跳动。人物随世界年老去，已故者由继任者承接职责，旧事仍留在记录中。
- **继续修行与问鼎**：辅助行动收在“修行”；装备、随机际遇、人间／幽冥／天界、三道证与最终挑战继续可用。身在其他世界或处理中断时，先按提示返回人间或完成际遇／战斗，再续主线。

寿元与命损、两次有限延寿、真实经历产生的传承候选仍沿用原规则。每世结算最多解锁一项新传承，新一世最多携带两项；资源与境界重来，已挣得的传承、道证、世界结果和生平保留。

**20–30 分钟是一世的设计目标，尚未经真人计时验证。** 后世是三类有限任务，后续世代会继续对应谷地类别的任务；本版不提供无限新篇或完整 NPC 家谱模拟。

## 存档与旧版继续

自动存档仍使用原浏览器存储键 `baishi-wending-save-v1`，内容升级为 **version 2**。合法 v1 备份先严格验证再迁移：保留当世阶段、资源、战斗、随机状态与生平，**本世继续旧途，下一世进入新篇**，不会给旧人物补造药谷经历。v2 缺失必需字段、矛盾事实或非法进度会被拒绝。

若存档是无效 JSON、空字符串或读取失败，游戏不会自动用新人生覆盖。可读到的原始数据可先“备份原存档”，再导入有效存档并确认恢复，或明确确认重新开始；读取被拒绝时不虚构原始数据。自动保存写入失败时，内存中的人生仍可继续并导出备份，请在离开前保存。

请使用游戏内导出备份。换浏览器、域名或线上／离线版本时，可通过导入继续；浏览器对 `file:` 本地存储的政策可能不同。升级后的 v2 存档不能交给旧版程序读取；切换版本前先导出。

## 检查、构建与离线版

```sh
npm test
npm run check
npm run build
```

`npm run release` 按顺序执行以上三步。

| 输出 | 用途 |
| --- | --- |
| `dist/` | 静态站点，保留原生 ES 模块与相对资源路径 |
| `release/baishi-wending-offline.html` | 内嵌脚本、样式及本地 SVG 的单文件版，可直接打开 |
| `release/release.json` | 版本、UTC 构建时间、离线大小和 SHA-256 |
| `release/worker.mjs` | 常规构建后另行运行 `build:worker` 生成的普通 Worker 模块 |

离线 HTML 同时复制到 `dist/baishi-wending-offline.html`。构建不改写源码。开发模块版应通过服务器打开，单文件版无需外部运行资源。

Worker 打包需提供完整 40 位源码 SHA。在已核实的源码检出中，可对本地候选执行：

```sh
npm run release
npm run build:worker -- --source-commit "$(git rev-parse HEAD)"
```

此命令只打包，不发布。常规构建会重建 `release/`，所以 `build:worker` 放在最后。正式发布必须改用实际 GitHub 发行提交构建并核对健康元数据，不能把本地候选 SHA 当作已上线证明。

## 项目与内容

```text
src/app.js                界面与交互
src/game/engine.js        确定性纯函数引擎与严格存档边界
```

**本分支为1.2.0纸页候选；现有线上站仍为1.1.0药谷旧火。** 本轮仅完成源码／Node检查与本地打包，尚无1.2.0浏览器视觉、键盘交互或生产验收证据。现有生产站由普通 Cloudflare Worker 返回内嵌离线 HTML，计入 Workers 请求额度；具体额度以账号套餐为准。当前没有已配置的 GitHub → Cloudflare 自动发布。本轮沿用 GitHub 验证后由控制方通过 API 更新现有 `baishi-wending` Worker 的方式。`wrangler.jsonc` 中的 Static Assets 配置仅供以后单独迁移，不是本轮发布步骤。历史与本轮发行的区别、CI 和实际部署证据见 [部署说明](docs/DEPLOYMENT.md)。
