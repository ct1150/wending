# 百世问鼎：对话与选项版设计

日期：2026-10-25（上海）。状态：批准设计已实现并作为 2.0.0 发布；独立整分支审查、最终修补复核、完整发行门禁、生产 HTTP 与实际桌面路径验收已完成。实际部署源码为 `4dadfd046f1e1413e721a5679745272ef22e07fb`；320px／深色、物理手机、读屏与真人节奏仍未验收。本文保留原设计决定与示例；实际规则见 [产品规格](../../PRODUCT_SPEC.md) 与 [作者契约](../../story/dialogue-journey.md)，上线与具体观察边界见 [QA](../../QA_REPORT.md)。

## 1. 要做成什么

玩家打开游戏就遇见一个正在发生的困境，读一小段叙述和人物对话，选择自己的行动，看到别人和世界作出回应。下一步仍然在这段故事里。成长、冲突、物品、远行和轮回都使用这一种交互。

本轮解决两个问题：现有玩法要求在故事和管理页面之间切换；重复修行、磨血与重复后世任务削弱了叙事与重玩体验。只是折叠菜单不能解决它们。

### 用户已经确认的方向

| 决策 | 已确认内容 |
| --- | --- |
| Q1 交互 | 取消随时打开的修行、装备、旅行管理菜单；行动在剧情需要时出现。 |
| Q2 成长 | 关键经历带来成长，少量能力组合改变后续解法；取消反复刷修为、反复尝试突破。 |
| Q3 冲突 | 通常以 1–3 次有意义的选择解决冲突，取代普通磨血战斗；保留目标失败、损失与明示的致命危险。 |
| Q4 随机 | 随机主要决定遇见什么和有什么机缘；常规行动按已知条件确定结算，不在选择后暗掷成功率。 |
| 长线 | 同一个世界延续前世后果；第一世可以问鼎，不以死亡或固定周目数解锁主线。 |
| 本轮授权 | 用户回复“全部按推荐”；剩余细节由实施者按减法原则提出并明确记录，不继续逐项提问。 |

下面标为“实施默认”的内容是本次收束所作的设计选择，不冒称用户逐条指定。

### 方案取舍

已经比较过保留随时管理的折叠界面、把旧战斗按钮改写成对白、以及把所有行动放入情境的方案。选择最后一种：游戏复杂度转移到情境、承诺和能力的组合，主交互保持简单。代价是需要重写规则与补足剧情，不能作为一次 CSS 调整交付。

## 2. 一张页面，只有眼前这件事

**实施默认：**单列纸页，正文阅读宽度约 640–720px；沿用现有浅色、深色与减少动画支持。没有聊天头像墙、地图首页、卡组、技能树、资源卡墙或常驻底部导航。

- 页面主体为已发生的短段落、玩家刚才的选择、人物回应和当前选项。历史段落可在同一阅读流中回看；不要求另开日志页才能理解结果。
- 通常展示 2–3 个当前行动。无选择意义的相邻对白合并展示，不逐句点击“继续”。章末交接、死亡结算等确有状态边界时允许 1 个继续动作。
- 选项使用具体行动，例如“带温渡走旧水道”，不用“事件处理”“战斗”“管理”等系统名词。
- 成本和重要不可逆后果写在该选项旁。涉及寿元时同时显示当前余寿；物品使用写“用掉最后一包止血药”，无需打开背包查库存。
- 能力可以改写某个选项或解锁不同解法。内容作者明确写出至多 3 条适用选项，禁止把一个长列表截取前三条来满足界面限制。
- 不适用的职业或能力路线不铺成一排灰按钮。确有教学意义的缺失条件，可以用一句剧情解释；缺失能力不能堵死主路。
- 一个低调的“更多”入口放帮助、导入、导出和重新开始。它不放修行、装备、旅行等游玩动作。
- 旧章可收束为可展开的正文摘要；不能删掉已保存的历史事实，也不在整页重绘时把玩家强制拉到页顶。

首局继续采用“云归”作为默认道号，直接进入谷口情境，不填姓名、出身和职业表。流派由实际学过的能力和做过的事情形成；后续不再补一张职业选择表。

## 3. 策略来自什么

### 成长与能力

主章中的关键承担和完成的经历带来境界变化，并直接开放下一章所需的通行能力。必需成长不依赖随机事件、某一种可选能力、累计死亡数或刷取经验。

**实施默认：**每个大章最多有一次可选学习机会，一世经过人间、幽冥、天界得到至多三项新能力；再加最多一项转世传承。数量由有限机会控制，不设装备槽、洗点或换装界面。错过机缘仍能推进主线。

能力库首版以六种具体方法为内容目标：

| 能力 | 能改变的局部解法 | 不能替代的事情 |
| --- | --- | --- |
| 护人之术 | 在撤退或对质时保护一个暴露的人 | 不能同时保全所有人、所有物证和全部时间 |
| 识破虚言 | 发现言辞或契约中的矛盾，开启追问 | 不能凭空生成证据或知道尚未发生的事情 |
| 燃命破局 | 支付明示寿元，强行打开一条短暂通路 | 不能免费救回死者或撤销既成损失 |
| 药理通识 | 辨认药性，使用替代救治或稳种方法 | 不能无限产药，也不能把灰谷灵种复活 |
| 引魂灯诀 | 让失名亡者留下证言、辨识归途 | 不能把亡者当活人复原 |
| 定契之印 | 把双方实际同意的条款固定为可追责契约 | 不能强迫对方同意，自己也要承担契约 |

学习必须发生在故事行为里，例如留下帮忙救人而学会护人，不在剧情外出现“选一张升级卡”。选择是否留下、跟谁学、接受何种代价本身就是机会成本。

至少写出两处组合解法。例如“识破虚言＋定契之印”可以揭出并固定一项被隐藏的条款，但仍须有真实账证和愿意作证的人；“护人之术＋引魂灯诀”允许活证人与亡者共同陈述，但不能使两人曾受的损失消失。能力不能变成任何场景里都正确的固定按钮。

### 寿元、伤势和物品

**实施默认：**新流程保留寿元、伤势、少量具体物品与未完成的承诺作为代价。取消修为条、敌我血条和常规攻防比较；也不把旧灵石、药材经济原样藏到对白后面。新故事用有限的药包、证物、通行物和契约表达资源，默认不提供通用货币商店。

伤势采用“无碍／负伤／重伤”的可读状态，不自动把每次受伤变成固定扣点。每个造成伤势的选项写明后果；伤势只影响实际相关的方法。治疗在有限的休整、帮助或交换情境中发生，不需要反复按休息。

寿元耗费与世界经过的时间分别记录。燃命造成个人命损，不能顺带让 NPC 老去五年；长途远行和多年守候才推进共同世界年份。境界成长可以改变寿限，不能让年龄倒退。精确寿限和工期属于实现时可调整的平衡参数，不照搬为磨级设计的旧数表。

作者必须给每个可达的非结算状态至少一条真实可执行的后继。低资源退路可以失去物证、让步、欠下具体责任或放弃眼前目标；不能同时要求已经耗尽的资源。继续冒险的能力不等于保证此刻仍能获得最佳结局。

### 冲突与失败

冲突围绕局部目标展开：救谁、保住什么、让谁同意、以何种责任换通行。普通冲突一次选择即可结束，重要冲突最多三次。每次选择后局势改变，下一次不是换文案重复攻击。

失败分为没有完成局部目标、带着损失继续、以及死亡。前两者有作者写出的后续。死亡来自已经明示的致命风险、寿元耗尽或选择守望余生；不能由普通选项背后的隐藏掷骰突然造成。

“活着的退路”可以是不战而退、放弃本次问鼎、接受责任或以未竟之身继续行路。它不必无条件获得道证。真正走到生命终点时进入明确结算，不留下空白页。

## 4. 重玩的差别从哪里来

随机发生在承诺之前：筛选与当前世界相容的遭遇、学习机会和人物处境，选定后立即保存。界面读取、刷新、打开帮助或回看都不推进随机数。

首个完整版本至少有六个可选遭遇（每界至少两个）；每世每界选入一个适用遭遇，必要时使用有内容的无机缘过渡。主章、通行和必要成长绝不依赖抽中其中某一个。内容有限，不宣称无限生成剧情。

重玩差异同时来自能力组合、实际救援与承诺、谷地制度、幸存者和已完成道证。已经失去的灵种、已经死亡的人和已经兑现的事情不能被随机数重置。

后世任务要有稳定 ID、完成记录和适用条件。医馆、庄园、迁民任务完成后，后世进入它造成的后果或另一项未完成内容，不再把同一件事重新交给玩家完成。没有新内容时用短回声交接到后续主章，不伪装成新的长支线。

## 5. 同一世从药谷走到问鼎

| 段落 | 当前目标与关键取舍 | 如何离开这一段 |
| --- | --- | --- |
| 人间：药谷旧火 | 查证、救援、决定谷地安排；保留共守、接管、焚种迁民的实质差别 | 完成离谷交接与人间道证事件，确定获得进入幽冥所需成长 |
| 幽冥：亡者旧账 | 面对未被救下的人、旧契或失名者；承认损失、追责或承担有边界的代偿 | 完成幽冥道证事件，直接接天门邀约；失败路线保留具体未竟责任 |
| 天界：立约问责 | 带着真实的人间结果与幽冥记录面对天规；决定新规则由谁承担代价 | 完成天界道证事件，进入问鼎终局；准备不足也有撤回与继续承担的明确后继 |
| 终局：三界问鼎 | 使用三界实际成果与本世关系解决最后冲突；选择所立秩序及承担的责任 | 胜利、失去本次机会但活着、明示风险导致死亡，均有终场与结算 |

设计批准时幽冥、天界和终局属于待写内容；现已由 Task5 实现真实场景、后果与公开胜路。其历史功能定义保持如下，完成证据见 [QA](../../QA_REPORT.md)，不以章节标题替代实际内容。

三种谷地结果共用后续主章骨架，分别带入公开药簿、宗门旧契或迁民名册。每种差异至少在幽冥、天界和结局各得到一次有实质作用的回应，不能只换开场一句称呼。证物只有真的取得才存在；缺失者通过明确的代价或不完整陈述推进，不能自动补造。

药谷结尾提供“交接后继续远行”和“留下守望余生”两个在故事中说得通的去向。前者直接接下一章，后者才结束此生。谷地结局自身不会触发强制轮回。

三界道证永久保存。后世已持有的道证直接得到承认，主路跳过重复取证，改为当世必要的交接、关系和准备；不能强制重打旧关，也不能以祖先的友谊冒充今世与本人相识。已完成全部内容的通关档显示诚实的回顾与继续入口，不承诺尚未编写的新故事。

固定人物随世界年份老去或死亡。继任者接手职责和可传下来的记录，不继承死者的亲身记忆、年龄或私人关系。

## 6. 轮回也只是一段故事

**实施默认：**默认结算显示三句摘要：做成了什么、付出了什么、世界留下什么。详细生平仍可在同一阅读流展开。

最多三个结算选项直接启动下一世，不再先领奖、再填身份、再选装备：

- 如果已有携带传承，第一个选项为沿用它，另外至多两个为本世新赢得或由真实经历重新唤起的替换项。
- 没有携带项时，至多三个真实候选；没有候选则一个“带着这段记忆再次入世”。
- 每次只让一项传承在新人生中生效。累计赢得的所有传承仍保留为历史，其他传承可在相关情境中重新唤起，不被删除。
- 传承直接改变相关剧情方法，不增加常驻“使用传承”按钮。死亡次数本身不发放收益，不无限叠加属性。
- 世界事实、已得道证与生平独立持久化，不占这一项传承，也不随新生清除。

新人生以当前世界的一个具体局面开始，并在遇见遗物、后人或制度时回应前世，不要求完整重读入谷开场。

## 7. 开场与冲突的文字原型

以下是拟实现的内容和节奏样稿，不是已上线画面。示例中的“药包”和寿元数值属于新规则，不能直接写入旧存档。

### 首屏

> 谷口的雨打湿了药箱。沈芷抱着一个发抖的孩子，另一只手还压着伤口。
>
> “先搭把手。封谷的人就快到了，里面还有七户人。”

1. **接住孩子，腾出她的手。**
2. **撑起油布，护住伤者和药箱。**

两条都是具体的入场行动，改变眼前回应，不假装这一次选择已经决定所有人的生死。它们可以汇合到同一处真实困境，避免在初次打开时堆教学。

### 第一次有代价的选择

> 孩子安静下来。沈芷把仅剩的止血药推到你面前。
>
> “温渡在旧炉房。他知道封谷那夜发生了什么。药可以让他说完那句话，也可以留给今晚撤出的伤者。”

1. **带药去找温渡。** 用掉这包药，争取让他亲口作证。
2. **把药留给撤离的人，去查旧账。** 今晚有人用药；温渡的情况不会因此自动好转。

两条进入不同方法与后续，不用红绿颜色、善恶值或“推荐选项”替玩家做决定。

### 能力融入冲突

> 温渡已经开口，炉门却被守门人封住。你听出了他的话有一处矛盾；怀里的账页能把那句谎话坐实。
>
> 温渡低声说：“他们要的是那张纸。我还能走。”

假设玩家此时具备“识破虚言”、实际账页与可撤离的人：

1. **当面指出矛盾，要求见证人到场。** 保留账页；温渡必须留下作证，撤离会耽搁。
2. **交出账页，换温渡离开。** 保住人，失去原始证物；不会在下一段偷偷返还。
3. **带他退回旧水道。** 放弃这次当面对质；后续面对未公开的案情。

如果此时具备的是“护人之术”，作者写另一组适用选项，出现护着温渡冲出封锁的方法及明确代价，而不是额外叠出第四、第五个技能按钮。

下一段必须按选择改变人物位置、证据或局势，不接回一套“攻击／防守／强攻”。这一段最多再有两次决定，然后收束到成功、带损失继续或事前写明的致命结局。

### 离谷

> 新的药簿已经有人接手。沈芷把另一本旧名册交给你。
>
> “活着的人有了安排。名单上没回来的那些人，还在等一个说法。”

1. **把谷中事务交接清楚，带着名册去忘川。** 接入幽冥篇；实际带走什么按此前所得决定。
2. **留下来，守完这一生。** 明确结束此生，进入生平与传承。

## 8. 实现边界和旧存档

沿用原生 JavaScript、零运行时外部依赖、浏览器本地存档与单文件离线发行。无需引入运行时大模型、Ink、账号、网络生成或新托管服务。

建议新规则使用独立的 journey 模块和 version 3 存档；现有 version 1/2 先走现有严格验证。旧存档当前人生继续原规则，到结算时才可进入新规则，不自动中断战斗、重置资源或补造经历。保留原始备份；下一世转换完成并校验成功后才替换有效当前存档。

兼容界面只服务旧人生，新的对话人生不出现旧管理入口。旧玩家在结算看见一段准确说明：当世结束后改用一项情境传承；累计解锁、道证、因果、生平全部保留。当前携带的最多两项旧传承都可成为这次交接选项，若只携带一项可再给一个本世真实赢得的候选；不通过任意截取累计收藏剥夺当前携带项。

十种旧传承的来源记录全部保存。迁移映射必须逐项有定义，数值和物品奖励转为对应的情境方法或一次机缘，不把旧装备优势机械相加到新人生。未携带的历史传承保留来源，在有适用内容时重新唤起；如果首版尚未写出某项的新版作用，明确列为历史收藏，不能谎称已经生效。

世界记录必须支持同世多章：使用稳定的章次/事件标识及完成顺序，不能继续假定每条结算的世代严格增加。每个世界变化只结算一次；死亡先结算未竟事实，再写生平；重复点击、恢复存档和回看不得重复发奖。

## 9. 当前源码中必须修补的连接点

以下对照的是已发布 1.2.0 源码，不代表本设计已经落地：

- `src/app.js` 的 `renderUtilities`、`renderSupportingActions`、`renderWorlds`、`renderInventory` 和 `renderSetup` 仍构成管理流程；新的 journey 不调用这些页面。
- `src/game/story-content.js` 的 YG16 继续选项没有下一场景，三个后世终点同样止于结算；必须补成实际后继。
- `src/game/story.js` 的 `createStory` 只按谷地结果挑后世任务；新调度要检查已完成任务、世界事实与人物状态。
