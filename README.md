## 开始游玩

首页固定显示三个入口：**「踏入仙途 / 续写此生 / 游戏设置」**。读取首页不会创建人物、掷骰或请求新剧情。

- **踏入仙途**：为新人物取名并选择来处，默认开启实时人生。已有角色仍活着时也可另开独立旅程；原旅程保留，可在「切换存档」中找回，新开不会替旧角色结算或发放轮回奖励。
- **续写此生**：继续上次选择的旅程，首页展示人物与进度摘要；没有存档时说明原因并禁用。旧离线人生依原规则恢复，已保存的实时旅程也可切换继续。
- **游戏设置**：调整画面主题（山海墨金／跟随系统／宣纸浅色／静夜深色）和正文字号（标准／较大），管理存档的导入、导出与切换。导入需要明确确认，并先保留原有旅程或可恢复的原始数据；保存失败时不会直接覆盖原档。

剧情下方直接显示 **「历史对话 · 游戏设置 · 返回首页」**；顶部保留人物概况与详情入口。重新打开页面先到首页，同一标签页内刷新则恢复所在页面、创建草稿或当前剧情。实际死亡后显示一生总结、墓志铭、因果点和轮回商店；明确选择「步入轮回」并完成新人物创建才进入下一世。

本版本继续使用 Cloudflare Workers AI 的 `@cf/zai-org/glm-4.7-flash`，仅通过原 AI binding 调用，不读取智谱密钥，不接入付费后备。新剧情需要联网，玩家无需提供 API 密钥。模型根据当前事件、已发生的决定和规则收据生成不同应对，并提供具体的拒绝、结束互动或脱险路径；后端不会用通用观察/退出菜单替换现代生成场景的选项。无法通过校验的回应保留待续进度并提供重试，不能执行尚未完成的选择。

本轮界面范围见[山海墨金设计](docs/superpowers/specs/2026-10-31-cinematic-game-design.md)。原引擎范围见[凡人流 v7 设计](docs/superpowers/specs/2026-10-31-cultivation-v7-design.md)，验证与部署状态见[验收记录](docs/QA_REPORT.md)。4.5 的[连续流式体验方案](docs/superpowers/specs/2026-10-31-consistent-story-stream-design.md)继续生效。真实模型仍可能给出不合理的叙事或选择，生成延迟取决于服务；流式选项改善阅读等待，不能保证每轮内容质量或固定完成时间。4.4.0 的[直接发布授权与未完成验收](docs/evidence/story-coherence-2026-10-30/direct-release-2026-10-31.json)、此前[失败记录](docs/evidence/story-coherence-2026-10-30/release-blocked-2026-10-31.json)及[4.3 历史验收](docs/evidence/cf-glm-promotion-final-2026-10-30.json)保留。

## 凡人流 v7 如何运行

新建实时人物或完成轮回后启用 v7。已有实时人生和离线人生沿原规则继续，可从存档目录切换回来。

| 系统 | 实际行为 |
| --- | --- |
| 寿元与时间 | 统一显示当前年龄／寿元上限。闭关和赶路只增加年龄；血遁、禁术反噬才折损上限，服用延寿灵药只增加上限。 |
| 九境修行 | 炼气、筑基、结丹、元婴、化神、炼虚、合体、大乘、渡劫；突破需要实际修为和材料，必须主动选择，有失败、重伤和死亡风险。 |
| 出生与资源 | 灵根、体质、伴生遗物与初始功法各有优势和代价；炼丹、炼器、制符、布阵消耗实际资源，黑市销赃和高价值行动会影响暴露风险。 |
| 长期因果 | 一条终身命运和一个终极谜团；近期因果10、活跃人物5、仇敌5、未回收伏笔3、主线1、支线2。超出窗口背景化或压缩，完整历史仍保留。 |
| 长篇节奏 | 年度世界摘要≤200字，天道存档≤300字；导演安排主线推进、时代变化、卷结构和挫折后的逆转机会。机会仍需玩家选择与规则结算。 |
| 玩家行动 | 数字1—3执行当前选项；第四项接受可明确映射的自然语言。无法执行、目标不明或超出能力时原样提示，不消耗回合或发起生成。 |
| 三层界域 | 飞升、偷渡、空间裂缝和古传送阵均检查目的地与资源；成功带来伤势、资源或地位变化，失败不会假装抵达。 |
| 轮回 | 仅真实死亡后结算因果点；兑换体质、前世记忆、因果罗盘或遗物并带入下一世。领取记录和余额随新版备份保存。 |

剧情通常为200—400字，允许的重大高潮上限600字。每轮停在决策点，至少保留一条可执行的谨慎路径。模型负责原创演绎和伏笔表达，规则负责数值、成败、死亡和资源；结构校验不能证明每个新名字从未出现在任何作品中，也不能保证长篇文学质量。

## 选择如何改变人生

规则先结算选择的时间、资源、风险与关系，再将必要的剧情上下文交给模型生成事件、对话和下一组可执行选择。人物、承诺、线索和已发生的后果参与后续剧情；模型不能改写规则收据。旅行目的地、行动含义、角色身份、资源和时间提示都经过校验。

登仙和问鼎都是人生阶段，人物仍活着就可以继续。实时人生不设固定章节终点、回合数或游玩时长，只有寿尽或其他规则判定的实际死亡才结束此生。应用也不另加人为模型调用次数或 Neuron 累计预算上限。

服务保留 **Cloudflare Workers Free** 套餐，没有付费后备。平台的真实免费额度仍然生效：额度耗尽、网络故障或生成超时时保留已保存进度并暂停。条件恢复后可选择「重试续接」，也可「检查已有回应」；恢复不会重复结算同一个选择。等待时仍可阅读历史、导出备份。

完整历史保存在当前设备。生成时仅传输所需上下文；已保存的实时历史可由兼容前端读取和导出，新增剧情需要线上服务。不同浏览器、域名和离线文件的存储相互独立，迁移设备请先导出存档。

## 存档与恢复

| 模式 | 存储与备份 | 兼容要求 |
| --- | --- | --- |
| 原有离线人生 | v1—v4 存档；4.0 为 `version:4 / contentVersion:3`；使用原 localStorage 键 | 沿原规则继续；旧格式的 1,000,000 字符限制只适用于该旧存档 |
| 实时人生 | `version:5 / contentVersion:4`，IndexedDB 分页档案；导出 `.wending.jsonl` | 不以旧存档总量上限结束人生；受实际设备存储容量约束 |

实时数据库为 `wending-live-v1`、结构版本 3。旅程目录分页展示已保存人生，切换旅程保留各自的完整历史、待续事务与随机状态；新增剧情进行中不切档，也不会因切档自动重试。首次请求前保存不可变的生成上下文和能力模式；恢复时先查询并沿用原 attempt，只有服务端明确确认缓存已不存在才创建后继 attempt。旧实时备份继续使用格式1/2；v7 或带轮回领取记录的备份使用格式3，三种格式均可读取。出生和待续事务先保存；读取、写入或导入失败时保留现有档案。带 `relationshipVersion:1` 的新档保存累计关系，旧的未标记 V5 档保留原历史、pending 和状态哈希，不静默重写身份或历史。

回滚仍须保留数据库 v3、V5/CV4、v7规则标记、格式3备份与关系记录的兼容读取器；v7 的确定性规则不能在已发布档案中静默改写。存档损坏或空间不足时，请保留原档并先导出可恢复进度。

## 开发与构建

Node.js >=22，项目使用 Node 24。Playwright、Miniflare 与 Acorn 是开发依赖，浏览器发行包不依赖它们运行。

```bash
npm ci --ignore-scripts
npx playwright install chromium
npm run dev
npm run release
```

`npm run release` 依次执行测试、语法检查和浏览器构建，并重建 `release/`。后端必须在它之后打包：

```bash
SOURCE_COMMIT=完整40位源码提交 npm run build:gateway
```

| 产物 | 用途 |
| --- | --- |
| `dist/` | 静态站点 |
| `release/baishi-wending-offline.html` | 单文件离线游戏 |
| `release/release.json` | 版本、字节数与摘要 |
| `release/gateway.mjs` | 静态发行网关 |
| `release/backend/` | 完整 ESM 后端与模块清单；默认命令生成关闭推理的包 |

正式 AI 后端需要显式生产策略、已验证模型和实际账户证明。GitHub main 的自动发行只发布 HTML；Cloudflare 后端部署是单独步骤，详见[部署说明](docs/DEPLOYMENT.md)。实际页面版本和来源以 [`/healthz`](https://baishi-wending.ct1150.workers.dev/healthz) 为准。

旧模式的构建前模型创作工具继续可用，见[剧情创作指南](docs/STORY_AUTHORING.md)；它与玩家在实时模式中的联网生成是两条独立流程。
