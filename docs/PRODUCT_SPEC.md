# 百世问鼎 · 产品与玩法规划

版本：1.0 ｜ 日期：2026-10-24 ｜ 状态：首版已实现并完成本地验收，线上部署待账户授权

## 需求与问题

玩家希望体验一款文字修仙肉鸽：在有限寿元内经历不同际遇、选择功法流派、冒险突破；寿尽后根据真实经历留下传承，重生时遇见前世改变的世界，最终称霸三界。每一世需要有独立目标，跨世成长需要改变路线和选择，且有明确终局。

## 产品方案

制作移动端优先的单机网页版《百世问鼎》。以寿元作为行动预算，以功法、神通和法器构筑流派，以宗门、墓穴、药谷、魂债等事件记录跨世因果。采用原生 JavaScript 模块与 CSS，运行时不依赖外部服务。以 GitHub Actions 检查、构建并发布至 Cloudflare Workers Static Assets。

发布方案为独立 GitHub 仓库与 Cloudflare Workers Static Assets。实际仓库、部署运行和线上地址见部署记录；未完成账户授权时不将构建产物视为上线结果。

## 产品目标

- 玩家能解释一次寿元取舍、自己所用流派、前世对当前人生的影响。
- 第一局即可完整经历修行、事件、战斗与结算；重生没有固定次数要求。
- 提供人间、幽冥、天界与最终决战的实际可玩主线。
- 提供自动保存、导出和导入存档，刷新后不重抽随机结果。
- 普通人生目标约 20～30 分钟；这是设计目标，不是未经测试的统计结论。

## 核心规则

### 时间、寿元与境界

余寿 = 境界寿限 + 延寿增益 - 年龄 - 命损。历时行动同时推进年龄和世界年份；燃寿只增加命损。突破先消耗时间，活到突破完成才增加寿限。气血归零或余寿耗尽则结束本世。每世延寿丹最多生效两次。查看页面、换装备、保存不会刷新事件或推进随机数。

境界顺序为炼气、筑基、金丹、元婴、化神、登仙。上限与行动耗时由内容表配置。突破有公开成功概率，失败消耗时间并给予后续尝试补偿。满境界后不再无限突破或增加寿限。

### 单局行动

闭关：耗时并获得修为。历练：耗时并从符合条件的未见事件中抽取。休养：耗时恢复气血。炼丹：消耗药材和灵石并提供有限延寿。突破：修为足够时消耗时间尝试升境。游历三界：满足门槛后切换区域。挑战道证或终局：进入关键战斗。归隐：结算当前经历。

### 构筑与战斗

流派为剑修、体修、丹修。装备槽为一门本命功法、两个神通、一件法器。装备和传承提供可解释的攻击、防御、气血、修炼或燃寿收益。战斗提供普通进攻、防守蓄势、燃寿强攻和撤退。强击意图可见；战斗本身不按回合让世界跨年。战胜道证对手获得不可重复的主线证明。

### 跨世状态

角色的境界、年龄、气血、一般资源重新开始。最多两项传承带入下一世。已获得的传承库、三界道证、世界因果与生平档案保留。结算只允许从本世真实经历产生的候选传承中选择一项解锁，已经拥有的传承不重复领取。转世在新身体 16 岁觉醒，世界年份相应推进 16 年。

每次结算保存最近 40 条关键日志和选定传承，历史最多保留 50 世。旧 v1 存档可继续导入；旧档中已经缺失的日志不做推测补写。

世界记录少量有后续内容的标记，不模拟所有 NPC 的完整人生。药谷、剑宗、墓穴、魂债等标记影响事件筛选和结果。凡人故友通过后人、旧物和传说延续，不能无缘由长生。

### 三界与终局

人间侧重入道与道统，幽冥侧重魂债与轮回，天界侧重天规与飞升。三界道证属于永久里程碑，现实盟友与角色实力需要当世重新准备。集齐道证、达到登仙并在终局获胜后成为三界共主。无需固定周目数。通关后展示结局，可选择新的轮回继续体验。


### 2026-10-24 有界平衡校准

校准只调整既有境界与终局对手的数值，不增加强制死亡、周目次数或新养成系统。前版后期寿限过宽，初始装备闭关至登仙后连续燃寿就能取得终局，装备与寿元取舍的作用不足。本版提高高境行动时间并收紧寿限，同时让终局对手要求实际构筑与应对强击。第一世仍然可以准备充分后直接通关。

三界共主为 1500 气血、125 攻击、55 防御。燃寿每次仍为五年命损；每第三回合的强击意图保持可见。延寿丹仍最多两次，每次耗当前境界一次闭关的时间、三份药材与十五灵石，增加两倍该闭关年数的寿限。故登仙炼丹每次耗二十四年、增加四十八年寿限，净增加二十四年行动预算，不能在余寿不足以炼完时使用收益回魂。

`tests/simulation.test.js` 使用真实创建、行动、事件选择、装备、战斗和保存边界，过程中不注入境界、资源、物品或传承。回归对每个流派运行三个固定种子的初始装备直冲路线，均取得三道证后在终局战死。另以 `prepared-2026` 验证三种第一世准备路线：人间十二次、幽冥十二次、天界十六次历练，选择实际可负担的奖励，装备当世取得的同流派或通用器物，服用两枚延寿丹，并在可见强击回合采用守势。每条路线实际完成三十四个事件，未使用前世传承。

直冲对比行使用种子 `legal-victory-2026`。动作统计包括装备、事件选择和战斗按钮；准备路线的三十四个事件之外，六次历练遇到普通敌人，均按正常战斗处理。剑修终局装备为星河截流经、焚星、回澜剑、劫灰剑鞘；体修为磐石吐纳法、托海式、落地生根、天工砧；丹修为九曜炉心法、枯木再荣、青雾回春、无极星盘。体修无需凑齐全部史诗装备即可通关。相同丹修准备路线改为每回合燃寿后会在终局战死，证明应对强击的守势会实际改变战果。

## 实现决策

- 规则引擎为独立纯函数模块：创建、行动、事件选择、战斗、装备、结算、重生、存档校验。UI 只通过这些边界改变状态。
- 内容使用可审查的数据表，事件定义条件、成本、成功或失败效果、物品及世界标记。
- 保存随机数状态，使相同存档与同样选择得到同样结果。
- 单一版本化存档包含当世、跨世和随机状态；限制字符串、数组、数值和可选 ID，拒绝损坏或不兼容输入。
- 浏览器本地自动保存，并提供显式备份导出与导入。存档不上传到服务器。
- 静态相对路径支持通用静态托管子路径，以 Cloudflare 为主要部署目标。无外链字体、图片、SDK、账号系统或付费 API。
- 构建复制完整运行资源，额外生成可下载的单文件离线版本；部署输出与源代码分离。
- GitHub Actions 先测试后构建，Cloudflare 部署工作仅在默认分支提交和手动运行且部署凭据配置完成时执行；也可使用 Cloudflare 的 Git 集成。

## 验证策略

核心测试边界是玩家公开操作后的状态，而非私有函数。重点覆盖：寿元与世界时间、突破失败及死亡边界、事件门槛与成本、装备限制、战斗胜负、道证只发一次、结算奖励来源、两项传承上限、重生重置和保留、随机重放、损坏存档拒绝与正常往返。浏览器验证覆盖实际开局、事件选择、存档刷新、重生、移动布局与资源加载。平衡模拟用于证明存在合法通关路径，不等同真实用户体验研究。

## 首版范围边界

多人联机、付费系统、排行榜、云端账号、即时大模型生成剧情、完整家族和宗门经营、无限境界、外部云数据库。后续可沿用内容数据格式增加事件与玩法，不影响这一版的可玩终局。
