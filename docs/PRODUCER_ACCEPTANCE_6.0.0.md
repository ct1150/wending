## 为什么分开测两种容量

[实际五回合存档](../tests/experience-story-archive.test.js)保存并读回每次冻结请求。验法、受助、离开、再遇、还粮的测试中，进入模型的剧情选择需要能还原到原人物 ID 和原未结事项；恢复后的状态摘要也须一致。API 上下文按普通 JSON 和再次转义后的 JSON 分别量测，两者均不能超 7,000 B。

[近满模型请求](../tests/story-available-actions.test.js)另构造密集上下文，检查动作 schema、身份、真实收据不为可选参考腾位而改写，模型总输入不超 24,576 B。它是生成端压力样本，不声称每个这样的合成输入都能由当前浏览器会话产生。

## 真人体验验收

真实服务和长线游玩与工程验收分别记账。以下项目需独立实测，阶段 CI 或历史版本数据不能替代：

1. 在兼容的实际服务上从开局完成一次短问答和选择，刷新后续接；分别记录首段出现时刻、读完到可操作的等待时长、是否被迫重试及原因。
2. 让两名玩家分别选择自研和求助，在看到结果前复述预期成本；事后问清自己付出了什么、功法哪里真的不同。
3. 跨日回到同一人生，让玩家辨认其目标和仍欠谁什么；不事先提示偿还方式。
4. 死亡后请玩家从结算中解释死因、关键决定，以及下一世要保留或改变的做法。记录其原话和真实复玩行为，不用通过率代替反馈。

GitHub 候选与正式域名可以处于不同版本。静态 HTML、后端能力、私有参考资料、真实模型和人类回访各自有独立状态；本次没有部署生产后端或上传语料。
