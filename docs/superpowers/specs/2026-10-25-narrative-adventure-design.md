# 药谷旧火：问鼎叙事冒险升级设计

日期：2026-10-25。用户已确认研究报告所述主线加随机分支、20–30 分钟一世目标、同世界轮回、剧情探索主导，并要求“可以，继续完成”。本设计是已认可方向的实施细化；具体技术和数值由实施者负责。

## 目标

把新玩家第一眼看到的体验从通用历练按钮转为能连续游玩的故事：有当下目标、有具名人物、有调查路线、有可理解的选择代价、有多种收束，下一世进入由上一世结果改变的后续故事。保留原有修炼、装备、寿元、传承与三界挑战。

## 已选方案与取舍

- 采用现有原生 JavaScript 的独立叙事模块，先完成可玩的内容；相比立即引入 Ink，没有编译/打包迁移风险。内容采用明确的场景、条件、选择和后果结构，便于以后迁移。
- 保留五种全局 phase，story 是 adventure 内的独立叙事状态；不用新全局 phase 改写全部既有操作。
- 用少量明确的世界事实与世代规则实现药谷历史；不做全 NPC 模拟。
- 保留旧存档当前人生，下一世才接入新篇，避免给旧人物捏造过去经历。

## 内容与玩法

首篇“药谷旧火”有三章，至少 12 个核心场景（实际可因路线取舍看到不同子集）、三名固定身份 NPC。至少两条路线在资源、关系、证据和后续解法上真实不同。证人、账册、地脉三条调查线最多充分追查两条；主线不靠反复随机抽取才出现。支线机会由种子决定，有限次、不能重复刷收益。剑修、体修、丹修各有可用专属解法；至少存在不战斗完成主线的路线。

结局至少三种：医谷共守、宗门接管、焚种迁民；提前寿尽、战败或归隐也留下未竟故事结果。第二世依据前世结果进入不同后续任务，有实际选择和结果，不能只换一段开场文案。人物本人/弟子/后人必须依世界年份与代际合理出现；已经死亡的人不可凭空复活。

场景应有可读的连续段落、人物动机与对话，不用一句数值通知代替剧情。选择后果必须在主要阅读区域保留，直到玩家继续。任务、线索和已认识的人可回看。战斗为短且可解释的剧情冲突，胜利、逃跑、死亡均有对应后续。世界事实只结算一次。

原规则中的修炼、休息、炼丹、装备、三界游历继续可用，但应明确对故事时间/位置的影响；不得在错误地点或战斗中选择剧情，不可跳过未满足的证据门槛。故事可以暂停，原行动不会抹掉剧情。核心冲突收束后可归隐轮回或继续三界修行。

20–30 分钟是一世设计目标，不能以自动通关或字数估算宣称真人时长已验证。

## 状态与存档

新存档 version=2；原 localStorage 键 baishi-wending-save-v1 保留，以便原站直接读到旧存档。

- 根对象 story：本世篇章、当前场景、有限旗标、已认识人物与关系、证据、调查进度、已读/已选记录、持续结果卡、剧情战斗回接位置、当前结局。
- meta.storyWorld：前世已结算结果、年份/世代、人物与组织事实、必要的后世推进记录。应有明确的容量上限。
- 与现有 run.flags/worldFlags 分开，避免未知标记破坏旧验证规则。
- deserialize 严格验证 v1 后迁移为 v2（先验证旧结构或通过严格等价路径），旧当世 story=null；保留 phase、战斗、随机状态、资源、历史、已选传承。不能补齐损坏的必需字段或吞掉未知字段。
- v2 新字段缺失或非法必须拒绝；序列化/导入导出可在所有剧情和战斗节点恢复。
- endLife 写 summary/history 之前结算未竟剧情；避免末刻已死亡却获得选项奖励。

## 对 UI 的公开接口

在 src/game/engine.js 新增：
- getStoryView(state)：无剧情返回 null；否则返回当前可展示模型。
- chooseStory(state, choiceId)：保持纯函数，不修改输入；验证当前阶段、场景、成本与条件，再返回新 state。

getStoryView 的最小稳定返回字段：
```js
{
  id, title, chapter, chapterIndex, chapterCount, sceneId, sceneTitle,
  location, objective, paragraphs: [],
  choices: [{id, label, description, costText, enabled, reason}],
  journal: [{title, text, year}],
  people: [{id, name, role, status, relationship}],
  clues: [{id, title, text}],
  lastResult: null | {title, text, changes: []},
  status: 'active' | 'resolved' | 'failed',
  outcome: null | {id, title, paragraphs: [], worldChange},
  progress: {completed, total}
}
```
实现者可加必要字段但不要改动这些字段含义。UI 从此模型渲染，不直接读内部 story 结构。现有 act/chooseEvent/combatAction/equip/selectLegacy/reincarnate/serialize/deserialise 接口保留。

## 界面

主界面优先展示章节、当前位置、当前目标、连贯剧情、人物/线索、明确成本的选择。资源仍可见，修炼等放进“行囊与休整”或“暂歇修行”辅助区。手机阅读行宽、字号、点击区域与滚动位置应可用。新手提示介绍剧情探索与轮回因果。旧存档给出“本世按旧途继续，下一世进入新篇”的明确入口说明，不自动清空或强制结算。

## 验收

完整走通至少两条不同首世路线、三种主要结局、三种结果的第二世后续。验证选择不满足条件不能执行、成本透明且只扣一次、无无限刷奖励、战斗胜/逃/死、寿尽/归隐结算、剧情中刷新及导入恢复、旧 v1 各主要 phase 迁移、畸形 v2 拒绝。电脑与窄屏真实浏览器验证主路径、存档恢复、无 JS 错误与横向溢出。静态版、离线单文件和 Worker 构建保持有效。

## 发布

在独立开发分支完成实现、检查与评审，经 GitHub 写入可审查提交，再更新已授权的现有 Cloudflare Worker。当前自动 Builds 尚无配置，发布可沿用 API MCP；最终以线上版本/源码提交、页面实际可玩、健康接口核实为准。不可把 CI 成功当成已上线。
