### 实时模式的边界

- 新档身份为 `version:5 / mode:cultivation / contentVersion:4`，规则与提示版本均为1；旧v1/v2/v3、V4/CV1/CV2/CV3继续原规则和原导入导出路径。
- 新出生快照增加 `relationshipVersion:1`，累计数值关系保存在永久索引中，人物离场本身不产生关系变化。重返人物只恢复有界关系工作集；客户端结算、后端校验、活动哈希、档案提交与导入重放使用同一规则来源。未标记的未发布V5档案保持原记录语义，不补写已经丢失的累计关系；v1—v4不变。
- 新开局先检验实际opening上下文，再持久化不可变出生事实。被拒绝的名字不创建活动档案、不请求生成，表单保留可编辑状态；普通中文和支持的标点可在修正后正常开始。已存在的旧待续档不会静默改名、重掷或修改请求身份。
- 规则先产生事实收据与待提交结果；AI只生成剧情、对话与行动意图。完整响应经过结构、机械事实和可执行选择校验后才提交。等待时显示最后已提交的人物状态，不用动画冒充流式生成。
- 生成候选在供应商返回ready前，必须对每个可执行且不导致本地死亡的下一选项检查必需上下文能否装入限制；不能先接受一个下一步必然超限的场景。超限返回 `NEXT_CONTEXT_TOO_LARGE`，保留原人物/待续事务，用户可明确重试。已完成但被拒绝的调用保留原日预留额度，不退还预留，也不当作跨日未知消耗；该HTTP整合修复专项与独立复核通过。
- 同一认证会话跨不同requestId共用一个30秒有效调用租约，SQLite短事务保证并发与重启后仍有效；完成可释放租约，超时只转为unknown并保留原有预留额度，不保证外部推理已取消。完成/未知分类由可信provider结果决定，不依赖对外错误文案；所有确定完成的拒绝保留原日预留额度，真正超时/传输未知才跨日保守占用。
- 出生事实与opening pending先存盘；choice与opening共用恢复事务。网络失败、额度暂停、过期会话、存储失败均可保留待续，确定未获准且有服务端身份绑定证明时，明确重试复用原attempt；其他需要新尝试的恢复使用新attempt并保留真实旧请求关联，不重复抽出生或结算行动。
- 当前相关人物身份/生死与规则收据是必需上下文；可选历史使用确定性 `relevance-v1` 检索并公开未解事项的总数、选入数与省略数。省略提示内容不删除原事实或承诺；完整档案与严格按引用读取仍保留，不能把一次提示的容量变成人生上限。
- 每128回合或256KiB封历史块，完整正文分页读取；`.wending.jsonl`流式导入先验证临时档案再切换。旧1M限制不是新模式终点，容量失败不能截断历史。
- 数据库 `wending-live-v1` 的结构版本为2，增加索引并通过原生v1升级保留数据验证。回滚前端必须保留兼容v2的档案读取器；旧V5数据库v1读取器不能打开已升级库，旧v1—v4 localStorage路径保持独立。
- 新增剧情需要同源HTTPS服务；只有capabilities协议兼容且明确available才允许开启。file页面、静态站点、缺绑定、旧HTML/后端回滚与关闭门禁都保持不可生成，兼容读取器可读可导出已缓存历史。浏览器和离线包不携带服务端Worker模块、账号证明或发布凭据。
- 账号每天免费额度为所有玩家共享，按当前平台规则北京时间08:00重置。应用预算是保守防护，不能替代账号Free硬边界证明；没有付费升级、credits或收费模型回退。

上述关系/分类/租约及未获准恢复/出生预检修复已通过独立源码复核，2026-10-27已审源码的539项完整代码CI也已通过。这些是实现合同；确定性fixture和本地workerd结果不证明真实AI的叙事质量、时延、计费或任意设备兼容。相关限制见 [QA](QA_REPORT.md)。

## 4.0既有玩法

## 目标与范围

从一个有来处、有牵挂的十六岁凡人开始，依靠师承、同伴、探索与取舍获得功法和突破材料，逐级修行到登仙。剧情围绕个人求仙、人与人的关系和跨世因果展开。新版不再固定从药谷开始；旧人生继续原有规则。

界面保持单列文字、人物对话与通常 2—3 项行动。顶部简栏展示姓名、境界、年龄、余寿；人物详情和完整历史放在抽屉中。没有资源面板墙，不在玩家界面展示模型、部署等实现细节。

## 一世修行与三界

道路包括宗门、散修与同盟，历险包括废墟、异兽和海域；竞争追索、物资短缺与天气改变处境。三组命运在创建时固定，下一世不会重复上一世的完整组合。匹配来信与历险线索会改变接引时间或补给，短缺会消耗行粮，风暴与追索会改变行程；这些结果只读已保存的机缘，不在查看场景时重抽。

当前内容有 **114 个可达的选择场景，另有一个结算场景**。数量不把命运组合排列重复计数；四种常规出身、三条立足之路与三类历险的 36 种主路线均有实际公共接口走通证据。正常完整问鼎路线为 68 次选择，不代表真人游玩耗时。

中后段围绕个人求仙与对手展开：与谢衡争取金丹灵髓、修习逆潮息诀并面对夺宝者；在幽冥辨认故人幻象、对抗缚魂者邵衡并凝练归魂印；攀天拆解殷无咎的雷印、通过顾沧残念的剑阵取得登仙遗物，最终完成鼎前约战。危险支线明确告知伤势、折寿或必死结果，稳妥路线也要付出真实年月。

初始凡人寿限为 80 年。六次突破必须逐级，伤势不超过轻伤；材料真正消耗，修为在成功后归零。先支付当前寿限内的真实年月，再获得突破成果，不能借用尚未获得的寿元。普通旅行按天，学习闭关按年；一年为 360 天，燃寿只增加个人命损。

完整通关需要实际抵达人间、幽冥、天界，取得三项道证，并修至登仙、赢下殷无咎的鼎前约战。资源、修为、伤势和已学方法决定选项是否可行。严重风险与缺失条件提前显示；没有无时间成本的循环刷资源。

## 归宿、转世与存档

死亡、寿尽、归隐或问鼎都产生真实生平与教训。转世最多携带一项亲身学成的方法；已留下的世界事实、道证与完整历史继续存在，世间推进十六年后新的人生开始。救援流民留下的互助棚会在后世开局增加可用行动；幽冥渡约则开启前尘行者与前尘回响。归隐和寿尽走完实际余年，问鼎在当前年龄结算，不强制把剩余寿命耗尽。

新篇使用 `version:4 / mode:cultivation / contentVersion:3`。CV1/CV2 由独立保留的原引擎处理；v1/v2/v3 旧存档仍走原分发规则。只有明确新开局才进入新版，不静默改写已有故事。

总存档上限仍为 1,000,000 个 JavaScript 字符，保留完整正文。超限行动原子拒绝，不扣费、不推进随机，也不截断历史。无效文件、读取失败与保存失败均有保留/导出路径。

## 免费剧情创作与发行

本地作者工具支持 Ollama 和显式指定的 OpenAI 兼容端点。模型只为固定插入位置提供文字候选，经严格结构校验、预览、作者明确接受后打入离线包。它不能添加规则、修改选项、奖励或结局；模型不可用时游戏照常运行。见 [创作指南](STORY_AUTHORING.md)。

仓库配置 GitHub 的 main 在验证通过后，将不可变游戏包和发行清单发布到 `release-channel`，发行任务使用仓库自己的 `GITHUB_TOKEN`，不让验证任务持有写权限。部署后的 Cloudflare 发行网关按请求检查来源与 SHA-256，并在失败时保留已验证版本；网关程序自身升级另行打包部署。本轮已实际核验生产自动切换，`/healthz`、首页与下载文件的身份和摘要一致；后续具体服务版本继续由健康状态和发行记录确认。见 [部署记录](DEPLOYMENT.md)。
