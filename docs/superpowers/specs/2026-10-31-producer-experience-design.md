# 问鼎：选择、成长与因果体验设计

日期：2026-10-31（上海）  
基线：main `26f7789f80ff34ec4744425299a4e85714ee6be9`，5.3.0。  
来源：用户接受本轮制作人评审，并要求将 plan / todo 同步 Git、按文档逐步开发。

## 产品目标

玩家能说清眼前目标、不同选择的代价，以及自己的决定改变了什么。完成一次重要突破后有可辨认的成长；死亡后知道下一世想换一种什么活法。

玩法保持凡人流文字修仙肉鸽：一段当前剧情、三个具体选择、一个自定义入口。一个当前存档，历世作为历史；直到实际寿尽或伤重死亡才结算，不设人生回合、章节、时长或应用调用次数上限。

## 当前事实与状态口径

- 5.3.0 已合入全本 RAG 代码；语料完成标记、生产启用及真实生成验收仍独立记录，不能由代码合入推定已上线。
- v7 已有确定性规则、长期导演、流式预览和事务存档。旧档导入会重放每次行动并比对状态摘要，不能原地改变旧规则。
- 当前生产人机界面仍有多旅程及离线入口，本设计收敛这些入口，但不批量删除用户旧数据。
- 仓库历史成功样本和界面 fixture 不等于本版本真实长线体验证据。

## 制作方案与取舍

采用“保留规则与存档基础，逐步完善一次选择的完整后果”。继续只换提示词无法使战斗与成长产生真实差异；全量重写会同时丢失成熟的流式、存档与恢复能力。新玩法以显式版本标记进入新人生，旧人生沿原规则继续。

实现采用现有 JavaScript ESM、Node 测试、原生 IndexedDB、Cloudflare Workers AI。无新增浏览器运行时依赖、模型提供方或付费后备。

## 1. 顺畅生成

1. 字数、高潮时机、转折标签和重复篇章类型属于编辑建议，不作为整轮拒收理由。简短询问允许简短明确回答，不填字、不补通用菜单。
2. 保留身份、实体生死、存档事务、实际成本与死亡、可执行动作、上下文容量及不可信数据结构检查。
3. 生成先承接玩家选中的具体目的与规则收据，再给当前结果，最后给不同应对。每个按钮都必须有可执行含义。
4. 外部 RAG 是增强资料。启用策略合法但语料缺失、损坏或读取超时时，使用已有有效游戏上下文继续同一次模型请求；不伪造引用，不修改调用记账，不增加自动模型重试。
5. 仅确定失败的生成提供清晰续接；在途结果仍按原身份查询，不重复结算。

## 2. 单存档与简洁界面

- 在线默认只继续一个当前人物。存活时“踏入仙途”指向当前人物；主动重开须在设置中明确确认，不发放死亡或轮回奖励。
- 移除正常界面的存档切换、离线下载、离线模式选择。历史旧档保持可备份恢复；不静默覆盖或删除不可读取数据。
- 轮回切到下一世；前世完整历史可只读查看，不可切回继续行动。旧多存档不再作为并列游玩入口。
- 合并重复人物状态。顶部显示境界、年龄/寿元；选择附近只显示实际成本、胜算概况和重要风险。
- 自定义行动保留原话，给出当前可用示例；解析失败不消耗时间、不发模型请求、不偷偷改写动作。

## 3. 新玩法的兼容边界

- 保留 V5/CV4、IndexedDB v3、rulesVersion=1、promptVersion=1 与 v7 主标记。
- 新人生可显式附加不可变 `life.birth.cultivationProfile.experienceVersion: 1`；有此标记才初始化可变的 `life.cultivationProfile.experience`。缺少标记的历史状态、收据、随机数和重放结果不变。
- 导演的新事件时钟也只在新体验人生存在，旧导演的派生状态不能被补写。参数与状态格式由任务3的接口合同定义并以测试锁定。
- 服务端 capabilities 宣告 `experienceVersion: 1` 后，前端才创建带新标记的人生。服务端回滚或能力缺失不得创建无法恢复的新档；已有新档保留并明确提示服务兼容问题。
- 所有新字段有明确边界并参与状态摘要。旧备份必须通过真实回放验证，不能用跳过校验实现兼容。

## 4. 开局与因果

- 根据保存的种子和出身选择至少四类开局结构：争取入门机会、资源压力、秘密暴露、关系取舍。开局围绕玩家自身目标，NPC 委托不再是唯一结构。
- 一眼能辨认人物的一项优势、一项代价和当前机会；保持姓名与出身的简短创建流程。
- 新叙事时钟由有实质后果的行动推进；普通零日询问/观察不推进时代或卷节拍。存档 turnId 和真实 RNG 仍按原协议推进。
- 先完成一条“识别残法问题—选择解决途径—兑现代价—改善功法”的成长线。研习、自行寻材和求助分别有时间、资源或人情代价；至少两种路线能完成，玩家可拒绝或暂缓。
- 承诺明确记录主体、接受时的玩家行动、待兑现条件及后果。新线索不能自动被当作玩家已接任务。旧人物重新出现时带回具体未兑现事项。
- 主线目标可兑现，完成后允许新的目标接续；不把任务完成作为人生终点。

## 5. 成长与风险

- 新玩法交锋读取稳定的对手强度及自身境界，不能根据名称猜测敌人强弱。强敌、弱敌的胜算和伤势有可测差异，成长确实改善同一场交锋的处境。
- 以少量信息表达对手的当前目的和可利用条件。无法确定的情报显示未知，不假装精确。
- 当前功法与不可变出生功法分开。修补/改修消耗实际资源，完成后实际减少相应缺陷；旧出生记录保持原样。
- 选择前显示可解释的胜算档位和实际成本。精确概率可留在详情，不以长数字列表打断正文。
- 不靠强制增加重复点击、任意缩短寿元或固定章节死亡制造难度。

## 6. 轮回

- 新体验人生每次选择至多两项传承，保留原有点数与消费真实性；旧人生的历史购买合同不改。
- 结算展示真实死因、关键决定与遗留事项，不编造死前事件。下一世携带有限、可追溯的前世回响，作为机会/义务线索，不自动兑现奖励。
- 前世回响随备份保存；拒绝领取、重复领取、跨标签与导入回放均不能复制奖励。

## 7. 验收与发布

- 每个任务记录实现提交、针对性验证和审查；只针对具体风险增加回归。
- 核心场景覆盖短问答、拒绝离开、不同开局、两种解法、功法改善、同一敌人前后境界差异、承诺兑现、死亡重生、刷新与旧备份导入。
- 全套工程测试、语法与前后端构建是发布门槛。真实模型成功、生产部署和真实玩家复玩另列状态，未执行就写待验证。
- 本轮候选版本为 6.0.0。代码通过 GitHub 分支与 PR 交付，CI 静态发行不等于后端启用。

## 不变量

Cloudflare Free、原 GLM 模型、现有绑定与账本继续使用；不添加付费回退、模型调用次数上限、固定游玩时长或固定回合终点。生产语料持久化授权与账号操作不借本轮代码工作绕过。
