## 开始游玩

- **踏入仙途**：为人物取名并选择来处。已有存档时先提示覆盖；取消创建会保留当前进度，确认入世且成功保存后才替换。重新开始不替旧人物结算或发放轮回奖励。
- **续写此生**：直接恢复唯一的当前存档，包括尚待续写的回合。没有存档时禁用；读取首页不会创建人物、掷骰或请求剧情。
- **游戏设置**：调整画面主题和正文字号。「备份与恢复」可导出当前 `.wending.jsonl` 存档，或在明确确认后用完整备份替换当前存档；校验或保存失败时保留原进度。

剧情下方显示「历史对话 · 游戏设置 · 返回首页」，顶部保留人物概况与详情入口。重新访问先到首页，同一标签页刷新则恢复当前页面、创建草稿或剧情。人物实际死亡后显示结算、墓志铭、因果点和轮回商店，明确选择「步入轮回」才开始下一世。

游戏通过网站运行，新增剧情需要联网；不再提供可独立游玩的离线版本。进度保存在当前浏览器，不同设备、浏览器和域名之间不会自动同步。更换设备前可导出当前存档。

## 剧情与玩法

凡人流修仙推演引擎 v7 使用九境修行、独立寿元结算、长期因果导演、自定义行动和真实死亡后的轮回传承。同一次 AI 请求连续输出正文、对白与三个具体选项；第四项允许输入自定义行动。生成和保存后的排版保持一致，选项在成功保存后开放执行。

v7 生成前复用游戏的实际资源、境界和目标规则，不让模型先提出付不起代价的行动。正文长短由事件需要决定，人物可自然使用别称，观察人手中的物件不必重复人物全名；正常内容直接保存，不额外自动重试。角色数值、身份、生死、收据和存档提交仍由规则保护。

| 系统 | 行为 |
| --- | --- |
| 时间与寿元 | 闭关和赶路增加年龄；血遁、禁术反噬折损寿元上限，延寿灵药提高上限。 |
| 九境修行 | 炼气、筑基、结丹、元婴、化神、炼虚、合体、大乘、渡劫；突破检查修为和材料，并结算风险。 |
| 出生与资源 | 灵根、体质、伴生遗物与初始功法各有特点；炼丹、炼器、制符、布阵消耗实际资源。 |
| 长期因果 | 人物、承诺、线索和既有决定参与后续剧情；窗口外内容可背景化，完整历史仍保留。 |
| 玩家行动 | 数字 1—3 执行当前选项；第四项支持可映射的自然语言行动，拒绝无效行动时不消耗回合。 |
| 轮回 | 仅真实死亡后结算因果点并兑换传承，领取记录随完整备份保存，不能通过恢复旧备份重复领取。 |

登仙和问鼎是人生阶段，不是固定终点；人物存活时可继续选择，游戏不另设回合数或游玩时长上限。规则结算时间、资源、风险与死亡，模型负责原创剧情和下一组选择。真实生成仍受模型质量与网络服务影响。

本次不改变生产模型、免费方案或剧情协议：继续使用原 Cloudflare AI binding 和 `@cf/zai-org/glm-4.7-flash`，不接入付费后备。平台额度、网络或服务异常时保留已保存进度与待续回合，可明确重试或检查已有回应，不重复结算同一个选择。

## 全本参考如何参与剧情

保留 5.3.0 合入的全本 RAG 代码。私有语料导入及实际启用仍属独立发布步骤，本次可玩性修复不改变线上知识库启用状态。

全本证据覆盖 137,443 个符合条件的叙事段落；广告、标题、空白和作者感言的排除范围有逐项核算。7,936 个窗口是可追溯的自动切片，120 张精选卡是独立的抽象改编层；不将窗口数量当作精编卡数量或逐条语义审校结果。[覆盖与重建说明](docs/knowledge/README.md)给出数量、来源校验值和准确边界。

检索优先匹配本次行动，避开近期已用片段，并保留明确拒绝、告辞和失败跨界的结果。每次最多加入一张精选卡和两个证据窗口，总模型输入仍不超过 24 KiB。资料仅提供冲突与动机的参考，不能替玩家接受任务、发放资源、移动位置或改变规则判定。只有成功提交的剧情才更新本局引用历史，重试继续使用原冻结上下文；旧存档的有效内容优先于可选检索字段。

知识库绑定、完成标记或选中分片缺失、损坏、读取超时时，生成会在模型调用前暂停，待资料恢复后可重试。后端启用需要显式生产配置与完整私有资料，GitHub 自动发布 HTML 不会自动开启这一能力。


## 单存档与兼容

沿用 `wending-live-v1` IndexedDB 数据库、结构版本 3 和既有当前存档指针。升级直接读取此前实际选中的在线进度，不按时间重新挑选人物、不清空数据库、不改写历史或随机状态。旧导航中的存档列表和离线页面回到首页。

出生与开局待续事务在请求剧情前一起保存，刷新不会重掷。成功保存新人物后，原人物不再作为可切换存档提供；生成暂时失败时，新人物的待续回合可恢复。普通继续不会替换已死亡人物的结算，只有显式重新开始或轮回才创建下一人生。

完整备份保留 V5/CV4、v7 规则标记、格式 1/2/3 和关系记录兼容。导入在完整校验后才激活，跨标签页使用事务与预期身份检查，旧页面和迟到回应不能覆盖已经替换的当前存档。

旧版 localStorage 原始数据和底层历史记录保留供兼容与恢复使用，不作为额外存档槽提供。检测到旧版原始数据时，设置中的「备份与恢复」提供原样下载；旧固定剧情不再接入游戏控制器。

## 开发与构建

Node.js >=22，项目使用 Node 24。Playwright、Miniflare 与 Acorn 仅为开发依赖。

```bash
npm ci --ignore-scripts
npx playwright install chromium
npm run dev
npm run release
```

`npm run release` 执行完整测试、语法检查和网页构建，并重建 `release/`。后端打包须在网页构建之后执行：

```bash
SOURCE_COMMIT=完整40位源码提交 npm run build:gateway
```

| 产物 | 用途 |
| --- | --- |
| `dist/` | 静态网页目录 |
| `release/baishi-wending-web.html` | Worker 内嵌网页发行包，需要在线服务续写剧情 |
| `release/release.json` | `frontend` 字段记录版本、文件、字节数与摘要 |
| `release/gateway.mjs` | 静态发行网关 |
| `release/backend/` | 后端与模块清单；默认构建关闭推理，不可直接替换正式生产包 |

GitHub main 自动发布 HTML，保留既有 schemaVersion 1 的频道清单与不可变摘要路径。正式 Worker 使用内嵌页面，仍需单独更新实际部署并核对版本；离线下载旧地址 `/baishi-wending-offline.html` 返回 `410 Gone`。实际页面身份以 [`/healthz`](https://wending.868656.xyz/healthz) 为准。
