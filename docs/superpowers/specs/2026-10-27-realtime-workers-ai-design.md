# 问鼎：选择驱动的实时生成与死亡终局

日期：2026-10-27（北京时间）。状态：**V5/CV4本地实现及专项复核完成；真实Free/模型/部署BLOCKED，生产已验收基线仍为4.0.0**。

## 用户已确定的方向

1. 取消“稳定20—30分钟一世”的目标，不再用现实分钟数、固定场景数或固定通关步数限制一世。
2. 根据肉鸽中的实际选择持续生成、推进剧情，直到人物死亡。
3. 使用 Cloudflare Workers AI，在免费额度内实时生成剧情。

“无限生成”指不存在预写主线终点，不代表人物不会死亡、免费算力没有额度或设备存储无限。长短由行动、修行、风险、伤势和寿元共同决定。新模式中登仙、问鼎、三界成就属于阶段进展，人物仍活着就继续；归隐可成为生活方式，不能自动结算一个仍活着的人。明确选择度过余生时，也须推进到真实寿尽才结算。

本设计中的版本、模块、预算、接口与测试取样均为**建议的实现默认值**，不是用户逐项指定的细节。实现与证据现已回填：1000回合fixture及 `4e44811` 的510项完整release通过，后续HTTP修复专项及独立复核通过；最终提交CI、整分支审查和真实上线门禁仍未完成，详见 [QA](../../QA_REPORT.md)。

## 规划时基线与当前差距

规划时 main 基线 `cbee9af7415fa547d37f3f428954cedeec5ab5f1`。CV3 使用固定 `NODES`，有114个选择场景；`v3/engine.js` 的 `enterScene` 和 `v3/validation.js` 校验目录，问鼎/归隐进入结算。现有68步通关只属于4.0验证，不能成为新模式目标。

`src/game/save-size.js` 将旧存档限制为1,000,000个JavaScript字符；CV3还限制正文/访问记录和历世生平数量。新模式必须拆分活动状态与长期档案，不能只放大常量。

原 `src/worker/release-gateway.js` 继续提供静态游戏GET/HEAD路由；现有构建另外打包完整多模块后端、保留DO类导出与绑定迁移描述。生产尚未部署该后端。只读检查生产 Worker 的绑定为 `[]`，没有AI binding。账号目录能查到 `@cf/qwen/qwen3-30b-a3b-fp8`；这不证明已经能推理、中文质量合格、还有免费余额或账号不会发生付费。

## 方案与选择

| 方案 | 取舍 | 本次处理 |
| --- | --- | --- |
| 扩写固定场景、构建前模型润色 | 沿用4.0架构，但仍有预写终点，不能响应任意后续人生 | 保留为旧模式，不作为新目标 |
| 模型同时决定全文与任意数值结算 | 自由度高，但容易凭空给物品、突破、复活或死亡，难以重试和校验 | 不采用 |
| 模型生成新事件和行动意图，规则引擎编译、结算并提供事实收据 | 情节可延续并响应选择，代价、随机、突破与死亡仍可验证 | **推荐采用** |

首版采用完整结构化结果的按需生成。点击选择后立即请求并显示等待状态，验证通过后展示下一幕；这属于实时生成。官方JSON Mode目前不支持streaming，不能把逐字动画当作已验证的模型流式能力。[JSON Mode](https://developers.cloudflare.com/workers-ai/features/json-mode/)

## 人生循环与规则边界

新模式独立采用 `version:5 / mode:cultivation / contentVersion:4`。旧v1/v2/v3与version4的CV1/CV2/CV3仍使用原规则，旧档不静默迁移。

每轮模型产生场景、人物对话和通常2—3个行动提案。提案使用有限规则词汇表达 `intent/targetId/stake/approach`，初始意图为 `practice,explore,negotiate,fight,evade,rest,travel,craft`；人物、地点和事件可以新增，但必须获得稳定ID并通过关系/事实校验。

引擎根据境界、命格、技能、资源、关系和已保存随机状态，将提案编译成明确条件、时间/资源成本与风险。模型不得直接提交年龄、余寿、境界、物品数量、修为、伤势、死亡或奖励。相同标签但不同目标、策略、资源与关系，应产生实际不同的机会和后果；不能只有文案换名。

玩家选中后，引擎先确定规则结果，形成不可改写的 `ActionReceipt`，下一次模型生成必须遵守。突破仍须支付真实材料和年月；已知致命危险应在选择前说明。只有规则确认的战斗/伤势死亡或寿尽进入结算；问鼎、刷新、等待、AI故障、配额不足和存储不足均不得触发死亡。真实死亡不依赖模型可用性，也不再请求死亡后的新回合。

模型可以提出新的关系与悬念，但不能抹除事实。已死角色不得无依据复活；回忆、亡魂须有明确身份与世界观依据。结构验证、机械事实收据、引用检查和实际长线审读共同降低矛盾，不承诺仅靠JSON校验消除全部自然语言幻觉。

## 可恢复的单回合事务

标识固定为 `runId,turnId,baseRevision,stateHash,choiceId,rulesVersion,promptVersion,requestId`。`requestId`在一次行动的待提交记录创建时确定，刷新不重新生成。

首次开场也走同一事务：`createLiveGame`创建出生事实已固定、`phase:awaitingOpening`的快照；`prepareOpening`生成 `kind:opening` 的PendingTurn，`choiceId:null`，事实收据只含出生事实，不扣资源、时间或重掷资质。出生快照与pending先在本地原子保存，再向同一预算/幂等API请求第一幕。刷新或生成失败继续同一个开场请求，不插入固定主线或绕过限额。普通行动使用 `kind:choice`，提交第一幕后进入active，真实死亡后进入dead。

1. `prepareChoice(state,command)` 校验revision/sceneId/条件，在副本中确定时间、随机和结果，产生 `PendingTurn`；先持久保存，不改变已提交人物状态。
2. 如果结果是实际死亡，直接原子记录死亡与历史，无需AI调用。
3. 否则向同源 `/api/story/turn` 提交有界上下文、事实收据及请求标识。服务端先检查会话、请求大小、幂等记录和账号预算，再调用固定模型。
4. 验证模型结果及其行动提案，客户端再次核对当前revision/stateHash；在一个IndexedDB事务里提交新快照、正文、记忆索引和已消费requestId。
5. 错误时保留原状态和待提交记录。双击、旧标签页、迟到响应不能再次扣费、发奖、推进随机或替换新回合。

服务端要持久登记 `pending/ready/unknown/failed`，重复请求先返回既有结果或状态。超时/断开不等于供应商没有消耗，也不保证推理已取消；未知结果按保守预算记账，不自动再发模型请求。用户明确重试前先查询原请求；确需新尝试时使用可追踪的attempt并重新预留预算，游戏行动仍只能提交一次。不能宣称外部推理绝对exactly-once。

匿名会话建议24小时有效，使用服务端签发的凭据和非敏感sessionRef；模型请求attempt绑定其sessionRef，记录在整个会话有效期内不得提前清除，容量不足时拒绝新请求。凭据不进入导出的存档。旧会话过期、记录已清理或跨浏览器导入后没有凭据，返回可恢复的 `paused/expired` 或 `paused/session-unavailable`，不能把查不到旧记录当作首次调用。保留原PendingTurn、事实收据与随机结果；用户明确选择重试后建立新会话/attempt，关联旧requestId并重新预留预算，人物行动仍只提交一次。不能保证跨会话取回已删除的原文，但必须允许在同一规则结果上重新生成。

## 连贯记忆与长期存档

- 活动快照只含当前人物、当前场景、近期回合、当前相关人物/地点、待解线索的索引。完整正文与事实日志进入IndexedDB分页档案，不复制进每次请求。
- 规则事实是权威记录；模型摘要是可重建缓存。保留人物生死/关系、承诺、取得与消耗、关键选择的稳定引用。旧线索可归档并按相关人物/地点检索，不能为缩短提示词静默删掉未解承诺。
- 历史按至多128回合或256KiB分块（先达到者封块），含顺序、摘要与校验值；活动部分有界。每回合只读当前相关档案，不能全量扫描历世正文。
- 相关上下文采用确定性relevance-v1选择：必需当前身份/生死/收据优先，未解事项优于可选事实，并明确coverage总数/选入/省略。省略不删除任何档案原文，严格引用检索仍可用于缓存提交和审计。每个可执行且不致本地死亡的下一选择须在供应商ready之前验证必需上下文容量；确定拒绝保留原行动与原日保守费用，可明确关联重试。
- 新模式使用独立IndexedDB数据库 `wending-live-v1` 与独立活动模式指示；保留原 `baishi-wending-save-v1` 和旧恢复路径。新快照、pending、历史块和记忆索引在同一数据库事务中更新。数据库结构已为v2（游戏档案仍V5），原生升级保留v1数据；回滚须保留兼容v2的读取器，旧V5数据库v1读取器不能打开已升级库。
- 导出为可流式处理的 `.wending.jsonl`：头记录、快照、顺序历史块、结束清单与校验值。导入先写临时档案，校验完整后原子切换；不得让部分导入覆盖现有人生。旧JSON仍走旧导入器和原1M限制。
- 新模式不能继承旧1M总量、30,000记录、300世的玩法终止条件。物理存储满时明确暂停、保留原数据并允许导出，不伪装成角色死亡，也不静默裁掉历史。

## Workers AI 与免费运行约束

截至2026-10-27，官方提供每天合计10,000 Neurons免费额度，UTC00:00即**北京时间08:00**重置。Workers Free超额会失败；Workers Paid超额可能自动计费。模型、Worker计算、存储都有各自限制。账号实际套餐、当前剩余额度和其他项目用量**本次尚未验证**。[定价](https://developers.cloudflare.com/workers-ai/platform/pricing/) · [Worker限制](https://developers.cloudflare.com/workers/platform/limits/)

严格免费是上线门禁：实施时先确认平台免费套餐硬边界或其他可证明的零付费配置。若Paid账号无法保证账号级零付费，保持实时生成关闭，记录具体阻塞；不得擅自升级套餐、扣预付credits、启用付费模型或更换收费后备。应用估算预算本身不能证明账号整体零费用，也不能假设所有免费额度都属于本游戏。

候选模型优先实测 `@cf/qwen/qwen3-30b-a3b-fp8`。模型页公开32,768上下文及response_format，但通用JSON Mode支持名单与模型页存在差异；必须用当前账号真实验证中文、结构、结束原因、思考字段及用量，不能根据目录200响应就勾选接入成功。模型配置可替换，发布时只允许已实测的免费模型白名单；不静默切模型。[模型页](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/)

初始建议：单次最多1536输出tokens，提示正文/结构总UTF-8输入上限12KiB，HTTP请求体32KiB，响应64KiB；服务端等待上限30秒，超过时保留unknown而非认为未计费。提示词还须符合模型上下文；若没有可靠token计数，按保守上界预留，不能把汉字数当tokens。首批真实接入、质量和生产闭环共用实验账本：最多10次，且保守预算不超过800 Neurons，先触及者停止；建议按4/4/2次分给Tasks1/7/8，如上界核算不满足则减少样本或输入。预算耗尽但验收未通过就保留未完成，不用模拟替代。

服务端使用AI binding `env.AI.run`，密钥不进入浏览器。SQLite-backed Durable Object负责短事务的全局日预算预留、会话并发和幂等记录；不在预算对象里等待整次推理，不依赖Worker内存/Cache API/KV最终一致性做严格扣减。该存储也须纳入免费门禁，保留期和自动清理有上限。[AI绑定](https://developers.cloudflare.com/workers-ai/configuration/bindings/) · [Durable Objects免费范围](https://developers.cloudflare.com/durable-objects/platform/pricing/)

预算按服务端UTC日期登记预留和结算，不能靠浏览器时间或简单清空计数器重置。跨日仍未知的请求，其保守上界继续从新日可用预算中扣除，直至实际用量核对清楚；迟到结算不得退还到错误日期，也不得因会话记录清理而释放未知消耗。预算账本与短期剧情缓存分开保留。免费平台硬边界始终生效。

所有玩家共享账号预算。服务端会话与IP限速、每会话至多一个进行中请求、请求/输出上限和全局预算须共同生效；CORS不等于防刷。对未确认预算、模型拒绝/截断、失败重试和未知用量保守记账。错误 `429/3036` 表示免费额度耗尽，停止自动重试；`429/3040` 表示容量繁忙，保留进度并提供有间隔的用户重试，不无限循环。[错误码](https://developers.cloudflare.com/workers-ai/platform/errors/)

额度不足、断网或模型故障时，玩家可阅读历史和导出存档，保持下一次待续选择；不暗中切回固定68步主线。新模式需要联网生成，仅缓存内容可离线阅读；旧4.0离线玩法继续保留。

## 部署、隐私与验收

在现有域名增加同源API路由，模块入口为 `src/worker/index.js`，将静态请求委托原网关，AI路由交给独立story-api。入口显式接收 `request,env,ctx`；绑定和Durable Object迁移单独部署。原main→HTML渠道不会自动安装新服务端绑定，必须增加后端构建、能力协商和发布门禁：先兼容后端，再前端启用；回滚保留旧档与待提交记录。

完整正文仍留在本地，但本次生成所需的角色姓名、状态、近期事件和摘要会发给Cloudflare；界面需简短如实说明，不继续宣称新模式完全不传输数据。服务端只保存有期限的请求/结果和预算记录，不默认记录全文日志。[数据使用](https://developers.cloudflare.com/workers-ai/platform/data-usage/)

验收不再使用分钟数或固定通关步数。用模拟供应商的至少1000回合长程测试验证无预写终点、活动状态有界和档案恢复；该数字只是测试长度。真实模型取样在上述预算内验证选择后果、人物关系、悬念延续、死亡、故障恢复和实际延迟/用量；不以模拟样本冒充真实推理，不承诺固定响应SLA。

对应顺序与文件接口见 [实施计划](../plans/2026-10-27-realtime-workers-ai.md)。
