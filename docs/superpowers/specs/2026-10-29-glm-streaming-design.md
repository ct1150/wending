# GLM 剧情流式生成与备用服务

用户最新确认：智谱标准 API 的免费 `glm-4.7-flash` 为主路由，Cloudflare `@cf/zai-org/glm-4.7-flash` 为备用；测试通过后发布线上并验收。优先让正文边生成边阅读；开局先展示本地出生事实和短引子。临时正文不进入正式历史，完整校验并保存成功后才开放选项；刷新只恢复正式回合及原 pending/attempt。所有代码由主代理修改。

## 方案与范围

采用同一次玩家事务内的服务端主备路由和 POST SSE。相比拆成两次独立的“正文/规则生成”，保持单个最终场景和现有提交边界。相比预生成所有选项，不为未选中分支调用模型。首版不预加载模型分支；保留后续基于实际速度和命中率评估的余地。

保留旧 Qwen profile、真实验收证据、存档和终态缓存。新增独立 GLM candidate，不把旧 Qwen 的 verified 标记复制给 GLM。没有真实模型证据时，不晋升新生产 profile，也不切换正常玩家流量。必要时使用有临时凭证的 0% 测试版本，验收结束恢复原部署。

## 实现边界

- Cloudflare 普通流式输出配合提示内 JSON Schema；服务端继续做完整结构、身份、规则和叙事校验。智谱使用固定官方标准 API、固定免费模型及 `thinking.type=disabled`，不允许前端提供 URL、模型或密钥。
- GLM 使用内部短引用协议：已知实体为 k1 等，新人物/地点/势力分别放入 otherPeople/places/factions；主角对白只用 self。服务端分配正式场景、选项及新实体 ID。模型只输出 action/targetId/stake，服务端按实际目标生成选项文字，减少复制哈希、角色混淆及文字与动作不符；不修补无效的业务状态。旧 Qwen 协议保持原样。
- `ZHIPU_API_KEY` 只从 Worker secret binding 读取。用户将自行配置；代码、日志、构建产物和浏览器响应不得含密钥。
- 智谱的非成功 HTTP 响应、限流、网络故障或超时可触发一次 Cloudflare 备用；没有智谱密钥也只尝试 Cloudflare。不循环重试，不升级套餐或调用付费模型。场景/业务校验失败不自动重新生成。
- 共用一个 90 秒生成期限，给备用留出时间。换源先发送 reset 清除原预览；失败/超时的调用不被视为退款或已知计量完成。
- SSE 事件为 status/reset/preview/result，绑定现有 requestId/attemptId/sessionRef。preview 只传正文增量，最终 result 沿用 V1 完整封装；原 JSON 客户端与缓存 GET 继续可用。
- 认证和持久预留在推理前执行。最终结果经服务端校验和协调器结算后才发出，客户端仍核对身份并以原 CAS 提交一次。断流不会自动重发；查询原 attempt 后才允许明确重试。
- 正文以纯文本局部更新，保持阅读位置、焦点及已打开的历史。状态变化可以完整渲染，正文增量不能重建整个 app。
- 正式生产包与受保护验收包固定同一次构建的内嵌 HTML，避免共享频道缓存将新后端配成旧前端。静态独立网关仍支持频道更新；以后正式前端更新需要和后端一起打包发布。发布以真实提交 SHA、构建摘要、版本模块读回和公开浏览器验收为准。

## 验证

以真实异步分片测试预览早于最终结果、中文 UTF-8/JSON 转义、无思考文本泄漏、上限和截断、主备切换、超时、最终校验、重复请求、缓存恢复和不重复提交。浏览器验证开局与选择流式、焦点/历史及刷新恢复。

首次验收时 Cloudflare 官方统计为今日 0 Neurons，但两个原生模型请求仍返回 429/4006。续测原生绑定仍返回 4006，该不一致未解决；不能解释为当天真实用量已经耗尽。智谱续测取得 HTTP 200、非思考及完整 usage 的有效场景，同时仍间歇返回 429/1305。

真实浏览器已完成开局、一次选择、保存与刷新恢复（修订号 2、RNG 一致、无新增生成请求）。浏览器使用本地当前构建页面和真实 Worker/SQLite；临时版本没有通过正式 GLM 晋升门禁，不能当作已发布证明。成功样本首段正文 1.1–14.5 秒、完成 5.9–19.8 秒，样本少且调试期间协议有变更，不计算 P95 或宣称稳定流畅。详见 `docs/evidence/stream-speed-2026-10-29/glm-followup-summary.json`。

## 预加载判断

输出开始后当前有效样本间隔约 0.3 秒，按每秒 6 字、累计 20 字开始阅读的产品测试假设，正文阅读覆盖了剩余生成时间。但 14.5 秒首段等待及服务繁忙仍不达 2 秒反馈目标。建议下一阶段评估阅读期间只预测一个分支，当前不启用额外模型调用。

预加载必须从已经保存的场景纯计算候选行动，不提前写入正式 pending 或推进随机状态；缓存绑定 run/修订号/stateHash/choiceId/规则/提示及模型版本。只有玩家选中并重新核验完整收据与场景后才能沿原 CAS 提交；选了其他分支、导入、换档或跨标签更新就丢弃缓存。服务器需要显式区分预测与正式请求，保留单会话在途约束及失败/unknown 计量，不能直接把现有 turn 接口当缓存调用。

上线前记录预测命中率、节省的点击后等待、浪费的推理量及是否阻塞真实选择；繁忙时暂停预测，避免免费接口拥塞被放大。预加载只能在命中时隐藏排队时间，不能解决平台拒绝服务。
